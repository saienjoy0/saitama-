# やってみクエスト：発表デモ v2.2

小学5年生の「なんで？」を、調べる行動・発見・ごほうび・家族の新聞につなぐ独立アプリです。
対象は `demo/presentation/`。既存 `prototype/gakusta/index.html` と本体DESIGN/D90は変更していません。

## 開く

配布用の `release/presentation-offline.html` をダウンロードし、Chrome / Edgeで開きます。画像・React・CSS入りの単体HTMLです。APIキーやネット接続は不要です。ファイルアプリのテキストプレビューではなく、ブラウザで開いてください。

ソースから起動する場合（Node.js 22.13以上）：

```bash
cd demo/presentation
npm ci
npm run build
npm run preview
```

表示先は `http://127.0.0.1:4173/`。開発は `npm run dev`。
buildで `presentation-offline.html` と `dist/` が生成されます。release版は今回のビルドから同じ内容を保存しています。

## 今回実装した体験

- 子ども：電気のつける時間、今月と先月の電気代、300円の飲み物、自分の疑問から選択。予想→具体的な3手順→比較→自分の発見。
- 補助：「何からやるか、一緒に考える」「困ったら、ここを見てね」。小5向けの短い具体的な言葉。任意の模擬AIをONにすると、疑問に対応する手順提案の表示例を確認できます。
- 写真は任意。カメラ対応のファイル選択・画像選択・2種類のデモ写真・写真の削除。JPEG/PNG/WebP、10MB以内。入力文は画像失敗でも保持。
- 子が記録を親に見せて申請し、親の承認で5pt。開始45pt→50pt。共有・写真の有無では加点条件を変えません。
- ごほうびを子が提案し、親が条件を承認。「今月500円」「毎月108円アップ」「ディズニーに行く券」「自分で考える」。必要pt・開始時期や条件を入力。
- ポイント交換は申請時に確保、親承認で一度だけ消費。「渡す予定」「渡した」「受け取った」を分離。継続増額は毎月自動消費しません。
- 発見が写真と言葉のアルバムに蓄積。本人の共有意思と親の掲載確認がそろった記事を選び、紙面を確認して新聞を届けます。祖父母のおたよりと家族の新聞アルバムに同じ号が残ります。
- 祖父母：今日の歩数（模擬）、歩数共有ON/OFF、「元気だよ」ワンタップ、任意の写真・一言、新聞・任意の返信。
- 親：子の申請と祖父母の安否連絡・共有歩数を同じホームで確認。歩数の更新日時と本人が押した日時は別です。
- 発表者バー：三役の切替、リセット、文字200%、動き抑制、歩数の未取得/0/前日、記録からの短縮開始。

## 3分の主経路：子どもの部分を省略しない

以下は時間配分の案です。実操作の所要時間は未実測です。事前にリセットし、ブラウザ100%で始めます。

| 目安 | 操作 | 話すこと |
|---|---|---|
| 0–20秒 | 子ども「これを調べてみる」→予想に「5時間で10円くらいかな」 | 「日常の明かりを見て、子どもが『いくら？』と思うところから始まります。」 |
| 20–40秒 | 「何からやるか、一緒に考える」→AIのお手伝い体験ON→「この順番でやってみる」 | 「答えを渡すのではなく、表示を探す・時間を変えて比べる・気づきを残す、の3つに分けます。今日は模擬AIです。」 |
| 40–65秒 | 時間を1→5へ動かす→2つのチェック→「自分の発見を残す」 | 「10W・5時間・練習用31円なら1.55円。予想と比べ、何に気づいたかは本人が考えます。」 |
| 65–85秒 | 「5時間で1.55円。長くつけるほど金額も増えた」と入力→電気のデモ写真（任意）→確認→新聞掲載にチェック→5ptをお願いする | 「写真は任意。発見がアルバムにたまり、親へポイントを申請できます。」 |
| 85–105秒 | 上部「親」→「5ptを承認する」→「この内容の新聞掲載を認める」 | 「親は発見の約束を確認。ポイントと家族への共有は別に承認します。」 |
| 105–125秒 | 「子ども」→おこづかい→50pt→交換をお願いする→「親」→ごほうび・承認→50ptの交換を承認 | 「発見でためたポイントを、親子で決めたごほうびに。今回は今月500円の例です。」 |
| 125–145秒 | 親「新聞を届ける」→紙面作成→「この内容で新聞を届ける」 | 「たまった発見が、本人の言葉を残した新聞になって届きます。」 |
| 145–165秒 | 「祖父母」→歩数を見る→「元気だよ」→おたより | 「祖父母は自分の歩数も見られ、ひと押しで無事を知らせ、孫の新聞を楽しめます。」 |
| 165–180秒 | 「親」→安否連絡を見る→アルバム→該当号 | 「親は子どもと祖父母を見守り、新聞は家族の新しいアルバムとして残ります。」 |

2分版は上部の設定から「発表の短縮開始（記録から）」を選べます。ただしAIの手順分解を見せるなら、上の3分版を推奨します。準備済みの架空体験を実家庭で実施済みとは説明しません。

## ごほうび提案の追加実演（30〜45秒の目安）

交換を始める前に、子の「おこづかい」→「自分のごほうびを提案する」。
「毎月のおこづかい108円アップ」を選び、「10月からずっと。見直すときは親子で相談」と条件を確認して提案。
親の「ごほうび・承認」で、その条件を承認すると交換対象になります。
「ディズニーに行く券」も同じ流れです。日程・予算・同行者などを親子で相談する約束であり、旅行を予約したり、公式チケットを発券したりはしません。

## 発表前に確認する分岐

1. 写真なしで申請→5pt承認→新聞へ進める。
2. 祖父母への共有を選ばずに申請→親が承認しても新聞には出ない。
3. 親がポイント/掲載を保留→それぞれ独立したまま。
4. 発行後、子の発見帳で記録を開き共有取消→既存新聞の記事も消える。獲得済みptは変わらない。
5. 交換申請を取り消す→確保したポイントが戻る。
6. 祖父母で歩数共有OFF・歩数未取得でも「元気だよ」は送れる。
7. 新聞の任意返信→子ホームの返信→次の疑問を本人が選ぶ。無返信でも次の探検は可能。
8. カメラ取消・不正画像→文章が残る。写真なしで進める。
9. 上部のリセット→初期2件/45pt/未発行/未発信へ戻る。再読み込みも同じ。

## デモの境界

記録はメモリ上のみで、リロードで初期状態へ戻ります。ポイント・ごほうびは架空の親子の約束です。実決済、実通知、実郵送、予約、永続保存、認証、実歩数取得、外部AI呼び出しはありません。
家族への「届いた」は同じデモ内の画面反映です。役割切替は発表者用で、本番の家庭分離や権限制御ではありません。
電気の31円/kWhは計算練習の仮の値で、現在の料金推奨ではありません。歩数と安否連絡から健康を判定しません。
画像は本タスクで生成した架空素材。詳細は `src/assets/README.md`。

最新状態は `DEMO_STATE.json`、引き継ぎは `CODEX_CONTINUE.md`。古い `src/App.tsx` と `src/state.ts` はv1の参照として残し、実際の入口は `src/PresentationApp.tsx` です。
