# やってみクエスト｜ChatGPT Work専用・販売仮説反復検証ハーネス

更新 2026-10-10｜研究のみ。本番実装・実際の販売は未開始。

## 実行担当はChatGPT Workのモデル
**DeepSeekのモデルは使わず、DeepSeek APIもOpenAI APIも使わない。** ChatGPTのWorkモード内のモデルが実際にリサーチ、比較、反証、改善を行う。外部CLIがChatGPTのモデルを勝手に呼び出すわけではない。Workを選んでタスクを開始する必要がある。

元のDeepSeek Harnessの「Goal（不変の目的）、状態保存、Round、批判・改善ループ、bounded handoff、停止条件」を**設計として移植**。DeepSeek公式DSH CLIのコードをそのままChatGPT Workに接続することはできない。DSHを起動するコードは削除し、純Pythonの非LLM検証スクリプトを残した。公式アーキテクチャの参照・SHAはUPSTREAM.lock.jsonに保持。

**開始するなら `WORK_START.md` をChatGPT Workに読み込ませる。** APIキー・DeepSeek契約・Node・npm不要。Workのブラウザ/コネクタと、GitHubへの書き込み機能を使う。Pythonは16セルの機械的検査にだけ使う。

## 対象
4つの販売シナリオ S1:裁量権 / S2:お金の相談 / S3:夕飯を任せる / S4:祖父母ギフト。
候補家庭 P1:任せ方 / P2:R・O・F・Bと相談の摩擦 / P3:生活体験と親の準備負担 / P4:祖父母参加。
**4家庭×4訴求を全交差した16条件**。顧客の実際の購入率を模倣した仮想数値は出さない。

2026-10-09の顧客研究を優先する。R/O/F/Bは面談後のPoC選択軸であり、既存10家庭の募集R1〜R4の代わりではない。
mainだけでなく製品PR #10〜#21を確認する。家族の裁量権、AIの教材→実行支援、親の気づきレポート、子のアルバム、祖父母の新聞・近況投稿、ポイントは設計/デモと本番動作を区別。

## Workの実行ループ（1つのユーザー開始タスク内）
1. WORK_START.md と最新正本を読み、`harness.py status`、`doctor`。
2. `harness.py prepare`（すでに第1ラウンドのREQUEST.mdは準備済みなら確認するだけ）。
3. ChatGPTが **Researcher** として、信頼できる原典・既存競合・実顧客の声を確認。
4. 同じChatGPTが独立した視点の **Critic** として、無料代替・家庭負担・継続理由・安全性を反証。
5. **Strategist** として、4案の訴求・オンボーディング・無料体験・4週間980円の仮価格・次回継続を改善。
6. **Auditor** としてソースと主張を照合、16条件を`rounds/round-NNN/RESULT.json`に記録。
7. 可能なら`python3 research/market-validation/harness.py verify`。検証が通り、新しい証拠がある場合だけ次ラウンドを開始。
8. **新しい証拠が尽きたらSTOP/NEEDS_REAL_CUSTOMERS**。4週間の実績/成約/2回目起動の数字は実家庭の観測がなければ不明とする。

最大3ラウンド、1ラウンド内の改善反復は最大3回。Workがユーザーの画面を離れた後も進められる場合はWork固有の挙動であり、このリポジトリがバックグラウンド実行機能を持つわけではない。

## 2026-10-10にこのチャットで実施した48分析パス
- `reports/48_passes_20261010.md` に**48/48パスの顧客課題→競合反証→修正/テスト**を記録済み。
- `rounds/48_desk_passes_20261010.json` に各パスのid/顧客/訴求/反対解釈/判断/出典キーを構造化して保存した。GitHub CIが48件・16セルの完全性を検査する。
- **48回の独立した実顧客テストではない。** 同じ文献の新規情報が48個あるわけでもない。ユーザーが要求した48回分の机上反証作業であり、残る購買・継続・子どもの反応は実家庭で検証する。
- Workはこの48件を読み、ただ再生成せず、**新しい公開証拠や実家族の実データを取得できた場合のみ次の更新**に進む。

## 記録
- `reports/first-pass-20261010.md`: 第0ラウンドの初期分析（公開調査・仮説のみ）。
- `rounds/round-001/REQUEST.md`: Workへの第1ラウンド指示。
- `state.json`: 準備・検証・停止の状態。未実行ラウンドを実行済みと表示しない。
- `harness.py`: 認証もAI推論も行わない、構造・継続ゲート検査。
- `HARNESS_PORT.md`: 上流DeepSeek Harnessのどの考え方を移植し、どの機能は移植していないか。
- `WORK_HANDOFF.md`: Work作業員への引継ぎ。

## 制限
