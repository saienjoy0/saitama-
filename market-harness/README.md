# やってみクエスト｜販売仮説検証ハーネス（2026-10-10）

**系統**：顧客検証／販売戦略（本体製品の BUILD ではない）。**開始状態**：設計済み・初回証拠監査を開始。本番のモデル実行／有料API／実顧客への接触は未開始。

## 目的
4つの販売シナリオ × 4つの探索用顧客像 = **16セル**を、実際の証拠を使って調査→反論→改善→次の実験へつなぐ。結論は販売の確約・AI生成の購入率ではなく、**何を誰に聞き／何を実際に売って判定するか**まで落とす。

- S1 子どもに何をどこまで任せるか迷う親
- S2 お金・外出・買い物の相談摩擦がある親
- S3 週末など実体験を任せたい親
- S4 孫の成長と三世代交流を応援したい祖父母

**重要**：4つのシナリオは4つの別商品ではない。同一の最新プロダクト（親子の裁量合意→AI補助で調査・比較・実行→本人の音声記録→保護者の気づきレポート→任意の家族新聞・祖父母の近況→次の経験）の異なる入口を比べる。

### ローカル／Workでの準備
Node.jsをインストールし、公式の `dsh` を**信頼できる公開バージョンに固定してから**導入。初回の検証環境だけなら `npx @deepseek-ai/dsh web` でUIが開くが、CIや自律バッチには `dsh --profile headless "..."` を使う。資格情報はユーザー管理の `$DSH_HOME`／環境変数、**GitHubへ絶対に置かない**。プレビュー版APIは変更され得るので、起動前に `dsh --help` と安全通知を確認する。

本検証に公式の `/goal` / `/loop` を無条件連続実行させない。ループは `runner.py` の外部状態台帳と回数上限で制御し、必要な時だけDSHヘッドレスを1セルずつ使う。個別AI応答は**仮説・反論であって、実顧客の声や購買実績ではない**。

## 使い方
作業フォルダで：
```bash
python3 market-harness/runner.py prepare --repo .
python3 -m unittest discover -s market-harness/tests -v
# DSH CLIを導入・設定後に限り、まず4セル・1反復・read-onlyの小試験
python3 market-harness/runner.py execute --repo . --max-cells 4 --rounds 1
# 残りも見る場合（手動で回数上限を指定）
python3 market-harness/runner.py execute --repo . --max-cells 16 --rounds 2
```
`prepare` は**モデル資格情報ゼロで動く**。16セルと出典状態を監査し、`market-harness/runs/` にブリーフと未検証一覧を生成する。結果はランごとに持ち、既存のファイルを上書きしない。外部で実際に記事を取得・確認していない資料を「確認済み」にしない。

`execute` はDSHが構成済みの環境でのみ実行できる。手動指定された回数のDSH起動に制限し、**勝手にSNS投稿、広告、メール、決済、ユーザーデータ送信、mainへのpush/mergeをしない**。`execute` で `--rounds` を増やしても新しい実証が得られない限り、結論の確信度は上がらない。

## 毎回の判定
- 現実の顧客の直近の行動か、公開一次データか、想像・モデル応答かを**必ず区別**。
- 16セルを同条件で比較し、購入者と子どもの利用者を混同しない。
- **既存代替**（LINE/口頭/固定小遣い/汎用AI/みてね/money ring等）で十分なら、それを勝たせる。
- 小5〜6の子どもの発言／写真／家計は記録も外部転送も**無断で行わない**。子どもが相談を恐れる家庭へ相談内容を親に自動通知する案は棄却。
- 4週間980円は **2026-10-06製品設計書内の検証価格案**であり、実際の価格・購入率ではない。
- PoCの成果は **子の自発的な2回目、親の準備／承認負担、価値の代替可能性、具体的な支払行動**で見る。祖父母はまずオプション。 
- 外部データが更新されないのにAIだけで同じ議論を再循環させない。現実の聞き取り・LP・決済が必要なら「実証待ち」で停止する。
