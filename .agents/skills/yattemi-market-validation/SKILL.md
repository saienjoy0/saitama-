# やってみクエスト｜市場検証

このスキルは製品実装用ではない。research/market-validation/README.md, AGENTS.md, config.json を読み、そこにある根拠分類と厳格な停止条件を守る。

## 実行
1. 2026-10-09のR/O/F/Bのターゲット正本と10家庭のR1〜R4募集枠を混同しない。
2. PR #10〜#21にある子ども・親・祖父母の体験と機能の実装状態を区別する。
3. P1〜P4家庭にS1〜S4の訴求をすべて提示する16セルを構築する。
4. 各セルで認知→無料体験→親の価値発見→具体価格提示→継続→解約まで障害と観測方法を設定する。
5. Researcher → Critic → Designer の複数視点を使う。DSHのsubagent/ralph/goalが使用可能なら境界付きで使う。
6. 反対仮説として、LINE・ChatGPT・みてね・金融カード・無料教材・口頭相談・紙の記録で十分な家庭を必ず含める。
7. 顧客の架空発言を「口コミ」や本物のデータとして捏造しない。購入率・継続率の架空数値を出さない。
8. 1ラウンドごとに指定JSONを保存してチェック。証拠更新が止まれば「NEEDS_REAL_CUSTOMERS」で止める。
9. 本番製品・個人情報・広告・送信・決済を変更しない。実家庭の観測が必要な場合は質問票と検証実験だけ提案。

## 優先する価値指標
- 子どもが親に促されず2回目を開始したか。
- 親が実際に準備・承認に使う時間が既存手段より減ったか。
- 子どもが安心して希望を話せるか（勝手な公開は禁止）。
- 親が価格提示後に契約するか。
- 祖父母参加が無いと起こらない価値があるか、LINEとの差は何か。

## 完了条件
最優先の顧客×訴求と、その時点では信じられない理由、直近1〜3か月の実際の出来事で確認する質問、最小実験、実購買・継続までの必要な証拠が揃った状態。存在しない証拠を埋めて完成にしない。
