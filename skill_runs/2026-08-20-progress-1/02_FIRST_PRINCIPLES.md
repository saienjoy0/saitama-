# First Principles — rerun with 今の進捗(1)

Applied upstream skill: `thinking-first-principles`.

## claimed constraints / conventions
Potentially mistaken as “must-have”: AI apprentice framing, support-profile model, exact five-step hint ladder, fading screen wording, photo, family newspaper, points, grandparent-first participation, app architecture.

## primitives retained
1. Child agency must genuinely increase, not merely appear in UI.
2. Child must have a real chance to notice, interpret, propose, refuse/modify and negotiate.
3. Some scaffolding is necessary for children who cannot yet do the whole loop independently.
4. Scaffolding should be targeted to the point of difficulty rather than blanket instruction.
5. Scaffolding must be reducible; otherwise the product can create a new dependency.
6. The child must experience a real consequence/value response from another person.
7. Family burden must stay low enough for repeated use.
8. Commercialization eventually requires a real payer commitment.

## discarded assumptions
- “Support profile” does not need to be a sophisticated persistent AI model. It can initially be simple observation notes.
- The hint ladder does not need exactly five levels; only the principle “least help first, stronger help only when needed” is binding.
- Fading support does not mean every child must follow one fixed timeline.
- Declining app usage is not automatically success; it is success only when replaced by autonomous real-world behavior.
- AI apprentice is not essential to the product core.

## rebuild
Minimum viable mechanism:
real household situation
→ child attempts to notice/explain
→ facilitator gives the smallest needed prompt
→ child proposes / modifies / negotiates
→ child acts
→ family returns lightweight concrete value feedback
→ child briefly reflects
→ next attempt starts with less help only where evidence supports reducing it
→ eventually child initiates from an unprompted real-world observation.

## binding residuals
- age/developmental differences;
- safety boundaries;
- family power asymmetry;
- parent burden;
- real-world willingness to pay;
- need to distinguish “less app use because bored” from “less support because autonomous.”

## kill tests
The mechanism is in serious trouble if, across repeated sessions:
- children only continue when externally prompted/rewarded;
- prompt removal causes the loop to disappear rather than become self-initiated;
- adults must repeatedly provide the actual answer/action;
- refusal/negotiation is not accepted in the household;
- parent burden is high enough that second use does not happen.

## changed conclusion vs prior run
The new progress strengthens one element from implementation detail toward **core mechanism**: not the specific support-profile UI, but the principle of **adaptive scaffolding that fades as capability grows**. That is now central to how the proposed service claims to produce autonomy rather than merely chore completion.
