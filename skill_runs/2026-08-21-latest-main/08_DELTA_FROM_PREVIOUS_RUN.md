# Delta from Previous Skill Run

## Previous center of gravity

Earlier run:
- first-session “want to do it again” was the clearest top risk;
- “problem discovery before a job exists” was treated as a stronger differentiation candidate;
- support fading was important but less fully operationalized.

## Latest center of gravity

The latest spec changes three major judgments.

### 1. Differentiation moved from “problem discovery” to “transfer architecture”

New competitive evidence means the project cannot safely say that competitors only manage pre-existing work. Problem discovery, ingenuity, child proposals, and reflection appear in competing offerings.

The sharper hypothesis is now:

**adaptive scaffold → only-needed support → fading → transfer of responsibility → spontaneous use in a new real-life context.**

This is still a hypothesis, not a proven moat.

### 2. Success moved from one top metric to an AND condition

It is no longer enough to optimize:
- repeat desire alone;
- support reduction alone;
- child proposal count alone.

The product must seek the intersection:

**repeat voluntarily × combined support falls × spontaneous new-situation behavior appears.**

This is a stronger definition because it prevents two false positives:
- “engaging but dependency-producing”;
- “educationally controlled but unpleasant/abandoned.”

### 3. Parent is now a clearer product-risk hypothesis

The latest spec articulates a plausible parent job:

> want the child to think independently, but daily life makes it faster to give the answer or do it oneself.

That can become the commercial wedge **only if primary behavior interviews support it**. Secondary surveys are not enough.

## New strategic contradiction that deserves explicit work

If the product succeeds, support and possibly usage may decline. This creates tension with a conventional subscription that rewards continuous engagement.

This is not a reason to abandon the concept. It is a reason to test alternative business structures later: finite cycles, progression modules, family/education programs, periodic new domains, or another value unit compatible with “graduation.”

## Current decision

Do not add more core features yet.

The next evidence should answer:
1. Can support actually fade across new situations?
2. Will the child keep returning as it fades?
3. Does spontaneous transfer appear?
4. Does the parent problem exist strongly enough to justify repeat effort/payment?

Until those answers improve, full-app architecture, detailed support-profile automation, family-newspaper polish, and advanced monetization remain downstream.
