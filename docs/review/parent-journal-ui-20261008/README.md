- **確認依頼**：40Pの夕飯実施報告は**親の確認待ち**。記事を読むだけで承認されず、内容と事前の合意条件を見たうえでチェックを付けてデモ上で承認。承認後は、画面末尾の「合成デモの操作を試す」から**50Pのごほうび交換依頼を別の操作として発生**させられる。交換承認は「予約・消費の検証例」であり、実際にカフェへ行った結果ではない。
- **初期状態に戻す**：同じ「合成デモの操作を試す」内のボタンで、依頼と確認の状態をリセット。

## AI・データ・安全境界

**実AIはつながっていない**。3記事の本文・発言・数値・イベントIDはデザイン評価用の**合成記録**であり、実際の子どもや親の発言ではない。このデモの「AIの記事編集」は、AIが将来扱う安全な表示部品のサンプルを**固定のコードで再現**しているにすぎない。ライブ音声聞き取り、文字起こし、サーバーの本人同意や家庭別認可はない。

- 現実の作業の状態は本人申告と親確認を区別し、先に存在しない理由、家族の発言、調理結果を作らない。
- 子本人の家族内記録と祖父母への新聞公開は別。同意・版・写真・宛先の承認がない合成記事を本当に共有しない。
- ポイントは家庭の事前合意に依存したデモ値（初回0P、調査20P、夕飯40P、カフェ交換50P）。現金の支払い・ポイントサービスへの書き込みなし。
- 現状のデータはブラウザーメモリ内。**再読込で初期化**。実サーバー通知・実歩数計・実健康診断はない。
- Codexの子ども画面や既存の祖父母画面は変更していない。別ブランチで独立した親のレビュー用HTMLを追加しただけ。
- 本番には、サーバー権限・利用者同意・出所ID検証・本人による記事修正・配信取消・送信成功ACK・永続化と履歴・AI生成の構造化出力が別途必要。
