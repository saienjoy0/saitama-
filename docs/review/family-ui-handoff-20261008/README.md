## 矛盾・修正案と適用範囲

1. **父母を別画面にする旧デモ／候補を入力欄へ移す旧方針**：今回の明示指示とPR #13の保護者統合を優先した。古いHTMLは変更していない。
2. **保存を報酬の条件にするPR #13と、保存・共有を必須にしない報酬設計§7.1**：任意の保存・共有と、本人の実行報告→保護者の活動確認を分離する修正案をこのレビューUIで具体化した。事前合意20P/40Pは架空の家庭例で、家庭の標準値ではない。
3. **祖父母の近況を親子に一律共有する旧HTMLと、宛先を本人が選ぶ製品設計§0.20**：既定は保護者（自分の子）のみ。孫への共有は追加選択。私的な活動記録も保存できる。
4. **旧AI候補契約と自由な相談・記事化**：通常のJSルール／固定文で模擬する。本番のAI入出力schemaや児童データ条件を変更済みとはしない。
5. **旧本体計画の水道題材と最新の家庭3シナリオ**：このUIの適用先・受入をPLANに整理した。本体計画、認証、DB、同意台帳への統合は次の別工程。D90を完了扱いにしない。

## 3体験の操作手順

1. 子どもで「クエスト→親子の約束」。最初の話す例と下部の次の例を押し、条件と最初の挑戦を本人が選ぶ。保護者で条件を確認し、子どもへ戻る。
2. 「家の調査」を開始。例を順に押す。収入40万円−確認した支出19万円＝21万円を表示するが、自由に使える額にしない。家族とのタイミング調整→一度試した本人の報告を内容確認→保護者へ確認依頼。例だけでは完了にしない。保存・共有なしでも20Pの確認へ進める。
3. 次に「夕飯づくり」。13段階の例を押して、材料・必要量・価格・迎え・本人の再判断・単価・本人確認付き実行報告・任意の振り返りへ。例は実際の行動と区別し、未実施・空欄・不明な報告ではその段階に留まる。実行報告を保護者が確認すると40P。
4. アルバム保存後、見せたい文章を自分で編集し、保護者へ共有確認を依頼。保護者は公開／修正して本人へ返す／保留を選ぶ。修正時は子どもの再選択後に公開できる。共有撤回と記録更新は過去の新聞号からも旧版を取り除く。
5. 祖父母は「おたより／これまで／私の近況」。記事を読む・日付と号を選ぶ・任意に「読んだよ」や自由な返信を返す。近況は自分の記録だけに残すか、宛先を選んで確認後に知らせる。
6. 子どもは「おばあちゃんから・次の問い」で返信から本人の問いと確かめ方を選べる。自分の問いや「あとで」も選べる。結果を本人確認して私的に保存し、希望した場合だけこの新しい記録も親確認後に共有する。元返信の取り下げ／記事更新後は新規採用できない。
7. 確定60Pからカフェ50Pを依頼→予約→保護者の確認一覧で承認→提供待ち→実提供の確認。予約取消／却下／未提供での返還はいずれも50Pを戻す。確定・消費を二重に計上しない。

模擬AIは限定した語句・段階に対応する。自由な言葉すべてを理解する実装ではなく、未確認や否定は保守的に止める。音声ボタンは既存Web Speech APIを保持し、利用不可時に文字で続ける。実音声・ブラウザー提供元への処理条件は今回検証していない。

次の開発では、同じ原本とブラウザーテストを保ち、記録の入出力契約・永続化／認証を別機能として進める。本番AI、実家庭への送信、実費用はそれぞれ設計と運用条件が必要。
