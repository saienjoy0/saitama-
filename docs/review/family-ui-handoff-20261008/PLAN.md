# 添付最新版からの家族体験改善計画

実行方式：native/sequential。ユーザーが指定した「分析・順序の提示後、機能単位で改善」に沿い、このセッションで逐次実行する。成果物はレビュー用模擬HTMLと検証証拠。旧B10〜B70の本体計画を再作成・承認扱いにしない。

## 目的と構成

子どもが現実を調べ、家族と相談して自分で選び、報告した内容から家族の記録へつながる体験を維持する。添付HTMLのCSSと夕飯の会話関数を土台に、小さい機能ごとの変更を同じ単体HTMLへ加える。会話の進行、保存した記録の版、共有同意・公開、活動報告・ポイント、特典を独立した状態で扱う。

子どもは短いスマホ操作で希望・判断を伝える。保護者は家事の合間に条件・共有・活動を必要時だけ確認する。祖父母は好きな時に許可済みの記事を読み、返信や近況の発信を任意に行う。未返信や共有なしでも子どもの活動確認は成立する。

## 対象ファイルと制約

- `baseline-upload.html`：添付をbyte単位で保存する不変原本。
- `index.html`：改善版。ライブAI・fetch・DB・実通知・実支払を追加しない。再読込で状態が消えることを表示する。
- `baseline.json`：原本hash、PR #10〜13の参照commit、比較元。
- `README.md`：出典対応、矛盾と修正案、操作手順、本番の未実装。
- `tests/review/family-ui.cjs`：Chromiumを動かす回帰・統合検証。
- `evidence/`と`verification.json`：操作出力、4画面幅の画像、検証対象hash。

必ず守る順序：本人の発言→模擬AIの返答→短い理由と出所／推測／未確認→現実で行うこと→本人の判断。役割は子ども・保護者・祖父母の3つ。数値、経験、家族の都合は本人の報告か明示した合成例からだけ使う。完了は実行報告、ポイントは保護者の独立確認。写真や共有を活動の達成条件にしない。
