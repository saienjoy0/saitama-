## 動作画面（従来の結合検証版）
- [親の画面](index.html) — 祖母・祖父それぞれの今日の元気連絡／歩数（手入力）／前回の送信、受信時刻。日付別の履歴。
- [祖母の画面](../grandparent-fixed-ui-20261008/index.html) — 今日の歩数を記録しても、それだけでは親に公開しない。「歩数を家族へ知らせる」を明示的に押して送信成功の後に親へ反映。元気ボタンとは別のイベント。
- 親画面下部の「合成デモの動作を試す」で祖母の元気・祖母の歩数・祖父の元気を模擬受信。さらに「祖母の画面を開く」で祖母側の操作を試せる（同じWeb配信元のディレクトリ構成が必要。単体HTMLのfile://閲覧ではiframeが制限される場合がある）。

## 祖父母から親への一周

1. 親で「今日の家族」を開く。昨日の祖母による元気・歩数記録と、今日の「未着」を区別して表示。祖父の未着も中立表示。
2. 祖母の画面で歩数5,200を**記録**する。親にはまだ届かない。
3. 祖母が「5,200歩を家族へ知らせる」を押す。合成送信の成功を経て親の「今日の歩数」に反映。
4. 祖母が「今日も元気だよ」を押す。歩数とは独立して送信成功後、親の「今日の元気」に反映。
5. 通信失敗を模擬すると、親の値は変わらず祖母には「未送信」。再試行可能。
6. 親の「これまでの近況」でそれぞれの履歴・送信時刻・受信時刻・歩数の手入力を確認。

## 信頼と安全

- 「元気だよ」は**成人本人が送った近況**であり、健康診断・安否の客観的保証ではない。
- 連絡のない日や歩数の少なさを異常・疾病・危険と判定しない。緊急通報、自動健康推定、監視通知は実装しない。
- 歩数は端末のセンサーを読み取らず、祖母本人が手入力した値に「手入力」と表示する。
- 実通信・認証・クラウドDB・家庭別アクセス制御・リアル通知・実際の歩数計連携なし。ブラウザーの実行中だけの合成状態で、再読込すると消える。
- 記録の公開は送信操作と成功結果を分ける。受信記録を「保護者が見た」と混同しない。

## 技術的な連携境界

- ブランチ: feature/parent-grandparent-updates-20261008。PR #16（祖父母デモ）に依存する差分として管理。
- 親新規ファイルは docs/review/parent-grandparent-updates-20261008/index.html。祖父母ファイルは docs/review/grandparent-fixed-ui-20261008/index.html のみ必要箇所を更新。
- 子ども向けの Codex 編集対象 prototype/gakusta/index.html と docs/review/family-ui-handoff-20261008/index.html は変更しない。
- 親は祖母iframeからの postMessage の **送信元ウィンドウ**と既知の familyId、memberId、kind、clientEventId、日時、歩数の範囲・出所を確認する。重複したイベントIDを拒否。**本番のセキュリティ保証ではない**。
- 種類は genki（本人の「今日も元気だよ」）と steps（0～99,999歩・stepSource=manual）の2つ。返信や子ども関連イベントをこの画面の健康・安全情報に変換しない。
- 実アプリ統合にはサーバー側の家族権限と認証、送信完了ACK、日時・記録元の保存、複数端末同期、同意、削除・本人の意思による発信取消が必要。
