# 祖父母の固定UI 実装（合成デモ） — 2026-10-08

## 使い方
[祖父母画面を開く（index.html）](index.html) を保存してブラウザーで開く。祖父母だけの3つの固定タブ「新聞」「アルバム」「今日」を用意した。子ども（はるちゃん）側の画面・関数・状態を変更していない。

**操作できる内容：**
- **新聞 G01/G02**：共有済みの合成記事（3つのクエスト例）→記事詳細→「はるちゃんが決めたこと／なぜそう決めたのか／結果／詳しく読む」。理由がない記事には架空の理由を生成しない。前後の記事へ移動できる。
- **任意の返信 G03**：記事詳細の「読んだよ」は一回タップだけで送信成功を模擬し、同じ記事の再送信を防止。「ひとこと返す」は **応援／質問／私の経験** を固定項目から選び、送信先・文章を確認してから「送る」。質問の初期サンプルは「今度はどんな料理を作ってみたい？」。返信を拒否しても新聞閲覧は完了する。
- **アルバム G02**：許可済み記事の写真を日付順一覧→拡大表示→前後の写真→同じ元記事を開く。サンプル写真の代わりに生成不要の埋め込みイラストを使用（実家庭写真と誤認させない）。写真がない記事も新聞では読める。
- **歩数 S25**：「今日」タブで0〜99,999の手入力歩数を保存（このタブの**ローカル実行中の状態だけ**）。端末の実歩数を測定したりAPI連携したりしない。
- **元気ボタン G04**：「今日も元気だよ」を一回押す→成功／失敗。歩数入力とは独立し、未送信日から健康・安全を判定しない。
- **障害系**：「今日」の「失敗時の動作を試す」で次の送信だけ失敗にし、未送信表示と本文保持の再送信を試せる。「A+」で記事本文と見出しなどが拡大される。
- **公開の取り消し（デモ用API）**：公開済み記事を取り消したら新聞・アルバムから消え、記事詳細が見られなくなる。

## 子ども側Codexと競合させないための分離
- GitHubブランチ：`feature/grandparent-fixed-ui-20261008`
- このブランチは `codex/ui-handoff-family-flow-20261008` を元に作成。**新規追加はこのディレクトリだけ**（Codexが編集するはるちゃんの画面／`prototype/gakusta/index.html`／既存`docs/review/family-ui-handoff-20261008/index.html` を変更しない）。
- 祖父母のUIは固定。**AIによる画面生成や返信代筆を行わない**。
- 実アプリへの統合では認証・家庭単位の権限・子と親が一致する記事版と宛先を、**サーバーで再検証**する。以下のJavaScript連携はセキュリティ境界ではなく、合成デモの接続用契約。

```js
  }

window.YattemiGrandparentDemo.getEvents();

```

### 実製品へ移す時の契約
- 読み取り：`article_id`、`approved_version`、`recipient_id` がサーバーの共有・同意状態と一致していること。祖母は公開された写真・文章だけを取得。家計・報酬・正確な所在は標準非公開。
- 返信：`article_id`・版・家庭宛先・返信種類・本人の文・`idempotency_key` を持ち、送信成功ACK後だけ「送信済」と表示。本人が書いていない理由をAIで補足しない。
- 子への戻し：`family_reply` は「おばあちゃんの質問／経験／応援」の出所付きでアルバムへ。子の次のクエストを自動開始させない。
- 歩数：取得元が手入力ならそのように表示。実端末連携は未実装で、許可と製品・プラットフォーム条件の検証が先。
- 元気ボタン：成人本人の意思で任意送信、返信や体調の推定とは無関係。
