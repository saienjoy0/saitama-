# 家庭体験の設計レビュー用デモ
2026-10-07 / 本体 DESIGN・D90の合成レビュー。発表用途の台本ではない。

## 開く
同じディレクトリの household-scenarios.html をダウンロードし、Chrome または Edge で開く。
1ファイルで動く。追加のビルド、ネット接続、APIキーは不要。
最初の画面で3本を選べる。①→②→③の連続利用も、それぞれの単独開始も可能。
入力は再読込で初期化。実家庭の個人情報を入れない。
CSSとJavaScriptが同梱されている。Githubのコード表示画面は実行画面ではない。

## 目的・構成
- ① 家族と役割、既に任されている範囲、予算、外出と荷物の条件を親子で確認。条件を後の体験へ引き継ぐ。
- ② 夕飯を支える仕事・家計・家事・在庫を家族に聞く／自分で見る。出所と本人の理解を分け、次の材料選びへつなぐ。
- ③ 献立・人数・在庫から買い足しを決め、店・単価・総額・量・時間・荷物を比較。祖母の来訪で3人→4人になり、本人が計画を変更し必要な相談を選ぶ。買物・帰宅・共同調理の合成場面を経て、本人の言葉を残す。

操作履歴と選択はJSONへ書き出せる。これは能力採点ではなく設計レビューの記録。
他の生活場面への応用は今後の検証対象。家庭の全てのケースの実装ではない。

## 主経路の試し方
1. ①で家族を確認→分担を聞く→予算1,000円・近所A店・1.5kgを確認→条件を決める。
2. ②で少なくとも家族の情報と在庫を調べる→自分の気づきを選ぶ→材料選びの係を家族に相談。
3. ③でカレー→在庫→3人分の肉300g/じゃがいも2個/サラダで720円の仮計画。
4. 祖母が加わり4人に更新→肉600g、じゃがいも4個、ルーを追加すると1,180円/2.1kg。
5. 家族にサラダの省略を相談→980円。父に迎えを頼み、運び方をA店16:30待合せへ変更→16:38帰宅予定。
6. 計画確認→買物をした合成場面へ→見本の子の声または本人の入力→共有希望は任意→振り返り。

別経路：予算1,200円への相談、母の同行、献立変更。
遠いB店は一部の品が安いが、当日の時間・同行条件を満たさない。
量や金額の客観的な不足を示すが、家族の価値観に単一の正解を与えない。

## 設計レビューの判定軸
1. 子どもが次に何を調べるか分かり、AIの答え待ちにならないか。
2. 得た情報が購入・献立・運搬の選択を変えるか。
3. 家族の相談が必要な理由が具体的か。親の準備や確認が過大にならないか。
4. 記録が生活の用事より重くなっていないか。
5. 未発言の理由や未確認の能力を自動で補っていないか。
6. 普通の会話と紙のメモに比べて、家庭条件の再利用と判断の引継ぎに追加価値があるか。

3本の利用体験を確かめてから、必要な機能だけを元の仕様と機能別の開発順へ反映する。
