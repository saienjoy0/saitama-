# わが家のたより｜アプリUI・掲載ルール・親の確認から月刊号発行まで
更新 2026-10-08｜非本番のUI設計案。実家庭への配信・本体実装は未承認（DESIGN/D90）。

## 0. この仕様の結論
- 同じ出来事を「本人の非公開アルバム」「共有許可済みの日付別の家族アルバム」「許可済み記事を編集した任意の月刊新聞号」で違う見せ方にする。入力・写真アップロードの二重作業はさせない。
- 新聞は家族の生活と出来事を伝えるもの。はるの選択理由、祖母の写真・元気・料理、親や祖母の本人のコメント、ごほうびに関する家族の約束を写真と短い言葉で見せる。承認画面やポイントの台帳は掲載しない。
- 父母の画面は一つの「保護者」。ただし保護者の健康・安全確認やクエスト全体の承認画面の詳細はユーザーの方針どおり別途設計。本書は新聞への共有確認・新聞号の編集だけを定義。
- 子の体験完了・親による実行確認／報酬確定・子の共有希望・親による公開許可・新聞号の発行・祖母の返信は別々の状態。祖母の返信や紙面発行がなくてもクエストは完了する。

## 1. Canvaをアプリに変換するルール
元デザイン：「わが家のたより 10月号」 https://www.canva.com/design/DAHXY-l9Caw/view （実際に2ページの本文を確認）。
1面ははると祖母のカレーの食卓写真、本人の選択理由。2面は祖母の朝食、親と祖母の一言、家族の特典交換。
ただし、**A4の紙面をスマホ幅に縮小して表示しない**。アプリは「写真→見出し→本人の言葉→詳しく読む」の縦長の記事カード型。月刊号をプレビュー・印刷する場合だけA4編集表示にする。
現在のCanva本文に「観からのコメント」や単独の「A」「B」「C」など生成由来の不自然な断片が残るため、アプリ側の本文の正本としてそのまま使わない。出所の確認できる家族のイベントから文章を組み立てる。

## 3. 再利用する3種類のデザイン部品

### 3-A 大きい特集カード
ヒーロー写真比率3:2、横幅いっぱい。写真に文字を重ねない。日付／投稿者→大きな見出し（例「はる、夕飯の買い物に挑戦！」）→一言の本人の選択理由（例「安いB店より、父の迎えに間に合うA店にした」）。本文は短く、買い物比較の表や詳しい事情は「この出来事を読む」の先。写真がなくても成立させる。

### 3-B 日常カード
祖母自身の朝食・散歩・料理写真は4:3を基準。本人の言葉「今朝は鮭を焼いたよ」を主役にする。歩数は送った日だけ「5,200歩（本人からの投稿）」等と出所を併記。写真だけの投稿に「元気だよ」や歩数を自動で書き足さない。

### 3-C ひとこと・特典カード
親と祖母のコメントは名前つき引用として掲載。投稿がなければ空欄も作らない。特典は写真なしでも成立する小さな「家族の約束券」。公式チケット画像やキャラクターは使わない。未実施の特典へ「行ってきた」と記載しない。

### 視覚と操作の仕様案
紙色 #FAF8F2、本文 #26342E、濃緑 #174D40、差し色 #AF735D を仮トークンとする。既存デザインシステムと衝突する場合は後者を尊重して差分レビュー。絵文字アイコンの混在は廃止し、1種類のSVGアイコン＋文字ラベルを使用。祖父母側本文18〜20px、見出し24〜28px、主な操作56〜64px、余白12〜20pxを試作値とする。200%文字拡大の実機検査は必要。

## 4. 素材別の掲載ルール

| 素材／出来事 | 私的記録 | 祖母に見せる家族アルバム | 月刊新聞号に載せる条件 |
|---|---|---|---|
| 子のクエスト・本人の判断理由 | 本人の原文とAIの補助を区別して保存 | 子が文章・写真・宛先を選択→保護者が承認した版のみ | 共有済みの版と許可された写真を再利用 |
| 子の写真 | 写真を保存しても非公開 | 選択された写真IDだけ承認 | 新しい写真や宛先は再確認 |
| 親のひとこと | 親本人の発言として保存 | 親本人が共有を選んだ時だけ | 同じ本人の許可範囲。引用をAIが創作しない |
| 祖母の「元気だよ」 | 祖母の投稿 | 祖母が家族へ送信したものだけ | **月刊号に再掲載する権限を別途確認**（安全側の提案） |
| 祖母の写真・朝食 | 祖母の投稿 | 投稿の共有先で表示 | 本人が月刊号掲載に同意した素材だけ |
| 祖母の歩数 | 本人入力／連携元の出所・時刻を保持 | 祖母が共有する設定の時だけ | 原則OFF。明示同意した場合のみ。健康を保証しない |
| 祖母の子へのレビュー | 祖母の原文 | 祖母が送信した相手に表示 | 本人の掲載許可。子を写す・特定する写真があれば子と親の共有権限も守る |
| 親の活動確認・獲得ポイント | 家族台帳 | 子・親の権限内に表示 | **ポイント台帳の自動転載なし**。本人が記事化を希望した出来事だけ |
| 特典交換 | 予約・承認・提供を別イベントで保存 | 状態に応じた説明 | 依頼＝「お願いした」／承認＝「交換が決まった、これから」／提供＝「行ってきた」 |
| 家計収入・詳細支出・住所・位置・健康情報 | 必要な範囲のみ | 原則非共有 | 自動掲載対象外 |

この「祖母の家族宛投稿」と「月刊号への再掲載」を別許可にする点、および歩数の新聞掲載デフォルトOFFは、現行GitHubの未確定項目を安全側に具体化した**新しい提案**。祖母本人の同意と利用者試験を要する。

## 5. 子→保護者→祖母→新聞の流れ

1. はるが声／文章／任意写真で現実の体験を報告 → **本人のアルバムに非公開保存**。
2. はるが「おばあちゃんにも見せたい」を押し、公開文／写真／宛先を確認 → **保護者の確認待ち**。この時点では祖母に届かない。
3. 保護者の「確認する」に「誰のどの出来事か／本人の原文／公開する文章と写真／宛先／AIの言い換えとの差」が並ぶ。保護者がその版を承認→**許可済みの日付別アルバムへ表示**。
4. 保護者が書き換え・写真除外・宛先変更した場合は子へ差分を返し、子が再確認したら保護者へ戻す。拒否・保留なら非公開。
5. 祖母は好きな日に記事を読む。返信・レビューは任意。祖母の料理写真や「元気だよ」は**祖母本人の投稿イベント**として独立に入る。
6. 許可済み記事だけが月刊号の候補になる。表紙＝主役1件、中面＝祖母の日常・家族の一言・許可された特典（存在する場合）を**自動レイアウト**。
7. 権限ある保護者が号の文章・写真・宛先をプレビューして任意に発行。発行しなくても許可済み記事の日付別閲覧は止まらない。
8. 記事の取り下げはオンライン閲覧へ反映するが、印刷済みの紙が消えるとは説明しない。送信／発行成功は実際の保存・配信応答の後だけ表示。

活動確認とポイント確定、新聞公開は別。祖母の返信がないと報酬がもらえない等の仕組みは採用しない。

## 7. 最低限の状態モデルと受入テスト

情報オブジェクト：Event（actorId、発言原文、根拠、日時、写真ID、非公開フィールド）、ShareGrant（eventId、公開本文・写真ID・宛先・版、子の意思確認、親承認）、NewsArticle（許可済みEvent／ShareGrant参照）、NewsIssue（月、記事ID、版、宛先、発行状態）、RewardEvent（申込／予約／交換承認／提供済み）。

| テスト | 成功条件 |
|---|---|
| NEWS-01 子の非公開保存 | 祖母・月刊号候補に表示しない |
| NEWS-02 親確認待ち | 実際の承認前に共有済み表示しない |
| NEWS-03 親が文・写真を変更 | 子の再同意を取ってから再確認 |
| NEWS-04 同じ宛先の承認済み版 | 祖母の日付別閲覧に即座に表示。新聞号を要求しない |
| NEWS-05 祖母が写真だけ送る | 元気・歩数を捏造しない |
| NEWS-06 祖母に歩数がない | 数字なし。健康・安全を確認済みと判定しない |
| NEWS-07 祖母本人が返信しない | 子の活動完了・ポイントは維持 |
| NEWS-08 特典承認だが未実施 | 「お出かけはこれから」。訪問写真を作らない |
| NEWS-09 投稿・承認・報酬を二度押す | 二重送信・二重ポイント・二重発行を防ぐ |
| NEWS-10 見せたくない写真を外す | その写真は記事・号・サムネイルに出さない |
| NEWS-11 祖母の家族投稿は許可、月刊号は未許可 | 日付別アルバムで読めても号には入らない |
| NEWS-12 月刊号発行に失敗 | 未発行・再試行可能。発行済みと装わない |
| NEWS-13 写真0枚・記事1件 | きれいな文字中心版。写真の提出を要求しない |
| NEWS-14 320/390px、文字200％ | A4縮小によらずカードとして読みやすい |
| NEWS-15 HSC-03新聞の公開 | 本人の発言・写真・家族の引用の出所と承認版を辿れる |

## 8. Codexへの実装分割

A：既存の子の記録を変えず、**許可済み日付別記事カード**を作る。
B：子の公開意思→保護者の1件確認→祖母への1件反映を縦断してテスト（合成データ）。
C：祖母本人の朝食写真・一言・元気を独立寄稿として追加。写真・歩数の出所と許可を保持。
D：HSC-03特集、親・祖母の本人のコメント、特典の記事を共通の写真中心レイアウトへ。
E：許可済み記事だけで「10月号」の編集プレビュー→任意に発行。印刷は後の段階。
F：祖母・親・子が実際に「読める／迷わない／自分の言葉が違っていない」ことを検査。

PDF・Canvaへの自動書き戻し、健康監視や歩数の判断、ポイント承認UI全体は本書の範囲外。

## 9. 未検証の事業仮説
月刊号が普通の写真アルバムより喜ばれるか、祖母が自分の朝食を載せたいか、親が共有を続けるか、子が理由を公開したいか、交換券の記事が家族交流に貢献するかは実家庭で未検証。最初のPoCでは「掲載内容を自分で選べるか」「1記事の親確認時間」「祖母が記事に到達するまでのタップ数」「閲覧後に家族と話題にしたか」を観察する。
