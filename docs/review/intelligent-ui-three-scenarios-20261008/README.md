## 何を見せるか

主役は小学5年生のはるちゃん。発表者がページをスクロールして見せる仕掛けよりも、子どもがスマホで使い続けられる導線を優先する。

1. 最初の画面で「🏠 初回の約束」「🔎 調査クエスト」「🍛 実践クエスト」を選ぶ。「クエスト」「やりたいこと」「最初のサジェスト」「声／文字の入力」だけを見せる。価格比較などのカードはまだ出さない。
2. 画面下部にあるマイクを押して話す。対応ブラウザーなら音声認識で文字化する。非対応・拒否の場合は同じ場所に文字入力。
3. 「はるちゃんが話した言葉」→「模擬AIの返答」→「今の情報から組み立てられたカード」が順に現れる。
4. はるちゃんが家族に聞く／家の食材を見る／値段を調べるなど現実の行動をし、戻って新しい情報を話す。実行や合意をAIが代行・確認したと見なさない。
5. **ここから上に戻る必要がない**：幅740px以下でアプリを画面の高さいっぱいにし、会話とカードだけスクロールする。**マイクと文字入力は下部固定**。新しい会話に自動スクロールし、次に話す候補を入力欄の直上へ置く。ソフトキーボードの表示位置にも合わせる。
6. 「わからない」とだけ話しても、その直前の話題についてヒントを返し、最初のメニューに巻き戻さない。実行を報告したら本人の発言から新聞の下書きを表示する。本人が言っていない経験は創作しない。

## 3シナリオをつなげる

| クエスト | はるちゃん自身がすること | AIの文章とUI（合成） |
|---|---|---|
| HSC-01 初回の約束 | 希望を話して親に何を任せられるか聞く | 希望整理→親子の約束カード→最初の一歩 |
| HSC-02 家の調査 | 家で仕事とお金のことを聞き、一つ提案する | 家族への質問→家計の一部を整理→試す提案 |
| HSC-03 夕飯 | 献立を選ぶ→在庫を見る→2店の価格→父の迎え→肉の単価と量→実行を報告 | 行動のステップ→金額比較→条件の再比較→単価→新聞の下書き |

## 発表用の具体的操作

- 端末で開くと、最初に子どものクエストとマイクが見える。「カレーを作りたい。4人分で、予算は1,000円」と話す。
- AI風の返答と行動のステップが現れたら、はるちゃん役が冷蔵庫を見る。戻って「家に米とルーがある」と話す。マイクは画面下部に残っている。
- さらに値段を調べ、家族に迎え時間を聞く。戻るたびに、**同じ位置のマイク**を押せば続きを話せる。画面を上にスクロールする必要がない。
- 上部の「📚 クエスト ▾」からいつでも別のクエストへ切替可能。発表者用の台本・再生は小さな「⚙」から別パネルを開く。客席には基本的に子どものアプリだけを見せる。
- 端末にマイクがなければ文字入力。任意のサジェストを選んでも未送信のまま。本人が書き直して「AIに相談する」を押した時だけ発言として記録する。

## 技術的な境界・検証

- **これは限定ルールと文章テンプレートの模擬AI**であり、ライブ生成AIによる自由対話やUI生成ではない。3シナリオの架空の台詞と合成金額を使う。
- 実家庭のデータや児童の生声は使わない。ブラウザー提供の音声認識サービスが音声を外部処理する場合がある。原音の保存、家庭への送信、DB保存はこのHTMLにはない。
- 本体製品の状態は DESIGN／D90、実装未許可のまま。デモは本体への実装承認や教育効果の証拠ではない。
- JavaScript構文と模擬DOMで、会話の開始、クエスト選択、価格・送迎時刻・単価、ヒント、次の発言、キーボードの余白、入力欄の固定CSS、全14ターンの台本対応などを検査。
- **未検証**：端末ブラウザーの実画面スクロール、320/390pxでの見切れ、ソフトキーボードによる被り、実マイクの日本語認識精度、児童の操作性。実機で要確認。
