# 声で3シナリオを進める「適応型UI風」デモ（2026-10-08）

**目的**：実際に声をかけると、本人の発言に応じて質問・比較・親への相談・途中記録のUIが変わることを短時間で見せる。3つの場面を一巡できるデモ。ユーザーの最新方針を優先し、固定のボタン順だけで進む前版より音声入力を中心にした。

## 今すぐ試す
[外部のHTTPSプレビューで試す（未検証）](https://raw.githack.com/saienjoy0/saitama-/7bb840532ba25a47421bf34e7d231e8d13069ad0/docs/review/intelligent-ui-three-scenarios-20261008/index.html)。これはGitHubのファイルを第三者のRawGitHack経由で表示するリンクです。最初に安全確認画面が出る場合があります。ここで音声が利用できるかは実機で未検証です。個人情報を入力しないでください。


1. [デモのHTML](./index.html) をHTTPSでホストする（マイク利用には通常HTTPSと許可が必要。単体HTMLをローカルで開くとブラウザーによっては音声認識不可）。
2. Chrome・Edge等の対応ブラウザーで開き、シナリオを選び、**「🎤 話す」** を押し、マイク許可の後に日本語で一言話す。
3. 認識された言葉に応じて表示が切り替わる。たとえば「A店は980円、B店は920円」→価格比較、「父はB店なら17時、A店なら16時30分」→家族の都合を反映した比較、「400グラムと600グラムで迷う」→単価比較。
4. マイクが使えなくても、下の文字欄へ入力して「この言葉で画面を変える」を押せる。サンプルの言葉もタップ可能。
5. 「次の場面へ」で固定の例を一巡できる。画面内の一時的な本人の言葉がまとめに残る。リロードで消える。

**マイクを使う場合の注意：** Web Speech APIの標準的な音声認識はブラウザーの認識サービスへ音声を送信することがある。**現実の子どもの情報や家庭の個人情報を入力しない**。デモで使うのは架空の例のみ。アプリ自身には録音・外部API・DB保存はない。Web Speech APIの環境依存を前提に、発表では事前に端末・通信を確認し文字入力とサンプルの言葉を代替として確保する。

- [MDN Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API)
- [MDN Speech Recognition の使い方](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API/Using_the_Web_Speech_API)

## 声で変化する3シナリオ

| シナリオ | 声の例 | 表示されるUI |
|---|---|---|
| HSC-01 約束 | 「予算は親と相談して、調理は一緒にする」 | 家族との取り決め・相談の整理 |
| HSC-02 調査 | 「父は在庫が分からないので、買い物の前に伝える」 | 家族に聞いた結果→情報共有の提案 |
| HSC-03 料理 | 「A店は980円、B店は920円」 | 価格比較 |
| HSC-03 料理 | 「父はB店なら17時、A店なら16時30分」 | 迎えの時刻・金額の比較 |
| HSC-03 料理 | 「400グラムと600グラムで迷う」 | 肉の単価・総額の比較 |
| HSC-03 料理 | 「A店で買ってカレーを作った」 | 行動記録・まとめ |

**大切な区別：** 音声認識はブラウザーで実際に行う。**その後のUI選択は固定のキーワード／条件ルールによる模擬判断で、LLMが毎回UIを生成するわけではない。** 値段・家族の条件・予定などは架空例。本人の発言と合成条件を混同しない。

## 技術・安全上の境界

- 1ファイルのHTML・CSS・JS。APIキーなし、バックエンドなし、LLMなし。必要時だけマイクを開始し、通常は単発音声認識。音声の原音をアプリで保存しない。
- 本人の入力・発言をHTMLとして実行せず文字として表示。体験の記録はこのページのメモリに限定する。
- 実際に行っていない調査や買い物をAIが自動で完成させない。行動と本人の判断はアプリ外。家族の合意・親確認・共有・ポイント支給を勝手に行わない。
- 実家庭のデータ送信、ライブ児童AI、写真・音声の保存などは別途承認と安全確認が必要。本体はDESIGN／D90・implementation_allowed=falseを維持。これはレビュー用合成デモ。

## 最小受入テスト

- 3シナリオを任意の順番で選び、入力した内容に対応するUIへジャンプできること
- 認識された文言をそのまま確認でき、表示が1回の発言ごとに変わること
- 価格→父との交渉→予算と量→実行の順で前回の条件と新条件を見分けられること
- 「マイク拒否」「非対応」「通信失敗」でも文字入力・例文で体験できること
- 本人が選ぶ・断る・ヒントを見るを保持し、AIが決定権限や送金を持たないこと
- 320/360/390px・文字拡大・キーボードで主要操作が隠れないこと

今回はGitHub上でJS模擬DOMにより音声イベント→各種UI切替の14チェックを通過。実際のブラウザのマイク許可・スマホ実機の認識成功・音声の精度・表示の視覚検査はまだ未検証。

## 2026-10-08 追補：発表専用「声→その場でUIと文章が生まれる」デモ

**最初に開く：[プレゼン専用HTML](./presentation.html)**。前の [index.html](./index.html) は音声の意図分類を見せる旧見本として残す。発表では presentation.html を使う。

### 体験をどう見せるか

1. **最初は簡単な画面**：「今日のクエスト」「やってみたいことを話そう」「最初のサジェスト」、マイクだけを中心に見せる。価格表・複雑なカードは最初から置かない。
2. **本人の言葉を受け取る**：「カレーを作りたい。4人分で、予算は1,000円」などと話す。Web Speech APIが使える環境では実音声から文字化。文字入力・発表者用のセリフボタンでも同じ後段へ進む。
3. **画面を『組み立て中』にする**：短い進行表示を出し、本人の言葉、生成されたように見える説明文、条件チップ、必要なカードを段階表示する。
4. **本人が現実で行動して戻る**：在庫を確かめる、家族に聞く、チラシを見るというアプリ外の行動を挟む。本人が新しい条件を話すと、同じ枠のUIが再構成される。
5. **最後に新聞・記録の下書き**：本人の発言を引用した下書きだけを表示する。現実の行動の証明や家族への発行は行わない。

### そのまま使える発表用の声（3シナリオ）

| シナリオ | 1発目 | 2発目以降 | 組み立てられるもの |
|---|---|---|---|
| HSC-01（初回の約束） | 夕飯の献立も、買う物も自分で決めたい。 | 親に聞いたら、献立は自分で決めていい。予算と道は相談、調理は一緒にするって。 | 希望を整理する文章→本人が決める／親と相談／一緒にする、の約束カード |
| HSC-02（家の調査） | 夕飯って買い物と料理だけでできるのかな？ | 父は店に行くまで在庫が分からないから、買い物前に知らせてみる。 | 家族への質問カード→実際に試す提案カード |
| HSC-03（料理） | カレーを作りたい。4人分で、予算は1000円。 | A店は980円、B店は920円だった。→父に聞いたら、B店は17時、A店は16時30分に迎えに来られるって。 | 調べる3ステップ→価格比較表→迎え時間を入れた比較表 |

料理で「400グラム520円と600グラム600円のお肉、どっちがお得？」と話すと、単価計算カードも出る。「買って料理を作った」と話すと、本人が報告した文章から新聞の下書きが表示される。

### 発表者の操作

- 右側は発表者用のセリフパネル。クリックすると**そのまま音声認識後の結果を再現**できる。実マイクが使えなくてもデモの流れが止まらない。
- 上部の「発表モード」で発表者用のパネルを隠し、子どもの画面だけを大きく表示できる。
- 「このシナリオを最初から」で一連の演出をリセット。
- 発表前にマイク・ブラウザ・通信を本番会場の実機で確認。失敗時はセリフボタンか手入力で同じ体験を披露する。

### 技術面と、できたと言ってはいけないこと

- **文章とUIは、発言から抽出した条件と、監修済みの構成ルール・文章テンプレートで毎回組み直す**。その場でLLMが自由に画面や文章を書いているわけではない。
- 対応ブラウザではユーザー操作で SpeechRecognition を起動する。Web Speech APIは一部のブラウザで利用不可で、音声がブラウザー提供元のサーバーで処理される場合がある。個人情報・児童の声を用いた検証は行わない。
- UIを先に準備するため、ライブラリは入れない。PR #11の紙色・緑色・カード原則、PR #12のHSC-01〜03、PR #10の音声を使って考え・行動を残す方針を参照した。
- 組み立てアニメーション（約0.5秒）はUI演出。実AIへの通信時間ではない。
- 本体製品は従来どおりDESIGN／D90。ライブ児童AI、共有、ポイント付与、製品実装を承認したことにはしない。
