# 3シナリオ発表デモ｜UI/UX改善記録（2026-10-08）

**対象・権限：** 発表用の合成レビューHTMLだけ。プロダクト実装やライブ児童AIは行わない。既存PR #13の変更。

## 問題の優先順位

1. **操作の入口が見えにくい**：子どもの発言を入れる欄とサジェストの意味が分かりにくく、サジェストを押すと意図しない即送信になる
2. **発表中の視線が散る**：右側に全セリフ・AI返答が常時長く表示され、重要な対話と生成UIが埋もれる
3. **小画面では発表者コントロールが下に流れる**：長いページの下にある台本を毎回探す必要がある
4. **会話と結果が長い**：直近2ターンと2つのカードが常時縦積みになり、最新の「本人の言葉→AI→UI」が小さくなる

## 変更したこと

- **子ども側：** 本文・返答の文字拡大、カードの縦一列化、補助カードの視覚的区別。返答済みの直近1ターンを大きく表示し、古い会話は折りたたんで読める。
- **サジェスト：** 押すと入力欄に候補が入るだけに変更。勝手に会話を進めず、本人が修正して「この言葉で進める」を押せる。
- **発表者側：** 右側の全台本を折りたたみ、**次の1セリフだけ**を大きく表示。発言全文・模擬AI返答全文・UIの見出しをセットで示す。「このセリフで会話を見せる」を押すと再生し、次のセリフへ進む。
- **スマホ側：** 操作用のパネルは原則隠して「台本・操作」から開く。会話の生成後は最新の会話へスクロール。「もう一度話す」で入力に戻る。
- **発表モード：** UIを大きく表示し、発表者パネルを隠す。戻す操作はヘッダーからできる。
- 親の承認・本物の家族共有・送金、実モデル生成については従来どおりデモ扱い。デザイン上の「AI」は**模擬の文章テンプレート**。

## 機能検証

保存後の最新HTMLをGitHubで読み直し、JavaScriptの構文・模擬DOM 23項目 PASS：
- 初期は簡素なクエストと入力欄、発表者用のSTEP数が6/4/4とシナリオに合う
- クリックしたサジェストは未送信で入力欄のみに反映
- ワンクリックで模擬のはるちゃん→AI→UIの流れが進み、次のセリフが提示される
- モバイルの発表者パネル表示と発表モード、会話とUIの表示、3シナリオの切り替え
- 価格・時刻・単価・新聞下書き、既存の監修済みUI文字列
- JavaScriptで外部モデルへのフェッチはしない、reduced-motion CSSの存在

**未検証：** Chrome/Android/iOS/Safariの実画面、マイク・本番発表の通信、320px実画面のはみ出し、200%拡大、キーボード/スクリーンリーダー、保護者・子どもの理解。模擬DOM検査のPASSを実機UX検証済みとは扱わない。
