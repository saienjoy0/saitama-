# 子ども・祖父母の先行実装と保護者画面の境界（2026-10-08）

> このドキュメントはCodexへの差分引き継ぎ用。既存プロダクトの本体ファイルを変更する指示ではない。PR #13のレビュー用ブランチに記録し、本体の `DESIGN / D90`、`implementation_allowed=false` の制約を尊重する。

## 決定した作業範囲

ユーザーの最新判断：**父母は同じ「保護者」画面**。ただし、保護者が祖父母の「元気だよ」・歩数・投稿時刻をどのように確認し、子どものクエスト希望・ごほうび希望・実行内容をどう見て承認するかという**画面詳細は後で共同設計する**。Codexが別途進めている既存実装を上書きせず、今回はそれ以外の体験を先行検証する。

今回の試作はチャット添付の **`やってみクエスト_子ども祖母_体験完成デモ_20261008.html`**（単独HTML、ユーザーへ渡したローカルファイル）。この文書だけではHTML自体をGitHubへアップロードしていない。CodexへHTMLを添付して参照させる。

## 今回デモで操作できること

1. はる：HSC-01「家族への相談」4発言、HSC-02「家の仕事の調査」5発言、HSC-03「おばあちゃんの夕飯」12発言。各発言はワンタップで模擬送信し、本人のセリフ→AIの返答→短い説明理由→出所・未確認→次の現実行動を表示。自由文字も記録するが、**自由文字に対して生成AIを実行したとは装わない**。
2. スマホでは下部に次のセリフを固定表示。毎回先頭へ戻って例を探さなくても続けられる。最新の本人とAIのやりとりが、次の発話候補より先に並ぶ。
3. 体験の途中または完了後、子の非公開アルバムへ保存し、以前の発言・理由を見返せる。子が祖母へ見せたい文章と宛先を選んだら**親確認待ち**へ。子自身の保存や共有希望だけで、祖母へ公開しない。新聞記事の事前承認済み**合成サンプル2件**で祖母の体験だけは一周試せる。
4. 祖母：新聞の最新・過去の記事を日付で読む。任意で「読んだよ」を一度だけ返す、経験談を返す（合成）。子のアルバムに祖母の返答を表示。
5. 祖母の本人発信：**「元気だよ」一回タップ、歩数手入力、一言入力、日付別履歴**。同じ日の「元気だよ」と歩数は1件の日付カードへ統合、重複タップで重複レコードを作らない。歩数不正入力は保存しない・入力文章を消さない。
6. 保護者：**設計保留の仮画面のみ**。将来の結合予定（親宛の共有希望、クエスト希望・実行、報酬希望、祖母の近況・本人発信日時）を説明するが、今は**実際の承認ボタン、健康・安全判定、ポイント自動付与を実装しない**。

## 重大な境界

- **「元気だよ」ボタンは本人の近況申告**。それだけで健康や安全を確認済みと判定しない。未投稿を異常、SOSや医療的監視と解釈しない。歩数は端末センサー連携ではなく本人の手入力で、入力元と日時を保持する。
- デモは**端末の画面内メモリのみ**。実際の家庭への通知／保存／同期／認証／緊急対応ではない。デモのAI応答と実行履歴は**合成台本**。
- 将来必要な親確認：①クエスト開始可否と条件・安全・費用、②実行報告／報酬確定、③ごほうび交換、④新聞に見せる本文・宛先、は**別の判断対象**。一括自動承認しない。親の負担を増やさないよう具体UI設計は保留。
- 本人の私的アルバムと、祖母に公開された素材、任意発行の新聞号は異なる状態。共有拒否・祖母返信なしでも子の活動は進む。
- 新規の家族近況を別居先へ送る機能や過去記録の永続保存を行うときは、同意、権限、削除・公開範囲、アクセス権、失敗時処理を設計してから実装。

## 実ブラウザーの検査

Chromium + Playwrightで幅 **320px／390px／768px** を検査：
- 3シナリオの全21発言、非公開保存、共有確認待ち、祖母に未承認記事が見えないこと
- 祖母の新聞・履歴・「読んだよ」・本人の「元気だよ」・歩数追記と1日1レコード
- モバイル固定の次発話、入力欄に一度置かずにワンタップ、会話とAI理由の表示順、左右はみ出し・JSエラーなし
- 異常歩数時に入力が残ること、保護者UIでは意図的に承認できないこと

これは合成UIの検査結果であり、実際の音声、生成AI、配信先の認証、歩数取得、実家庭での継続性・安全確認を実証したものではない。

## Codexで統合するとき

新HTMLの見た目をそのまま本体へ丸ごと貼り付けるのではなく、**体験イベントモデル（誰が何を言ったか／いつ／出所／確認状態）とコンポーネントを既存構造に写像**。ユーザーが保護者のUXを決める前に新しい親承認ロジックを発明しない。既存ファイルと衝突する時はCodex側の現行コードを優先し、**この試作との差分をレビュー**する。
