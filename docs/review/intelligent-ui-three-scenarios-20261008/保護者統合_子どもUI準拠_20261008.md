# 家族体験の役割再設計：父母を「保護者」に統合し、子ども用UIにそろえる

更新：2026-10-08 ／ 対象：発表用の非本番レビュー／本体は DESIGN・D90（実装未承認）。

## 今回の変更

4つの役割切替「はる／母／父／祖母」を、**3つの役割切替「はる／保護者／祖母」**にする。これは権限を消すことではない。家庭の実際の管理者・確認者の構成は設定で決める。本番では親権限の認証が必要で、画面切替ボタンはレビュー用の演出。

### 理由

- 旧版は母が共有だけ、父が実行・ポイントだけ。**親がひとつの出来事を確認するために別人物の画面へ移る**不自然さがあった。
- プロジェクト既存の `docs/design/やってみクエスト_主要導線と表示情報_20261006.md` は、役割を「子ども／親／祖父母」と定義し、親の入口を **「確認」と「家族の記録」** に集約する。
- `docs/design/role-experience-v0.3.md` の親画面型も P01確認・P02共有確認・P03成長アルバム・P04新聞号（任意）・P05家族設定であり、父母を別アプリにする要件はない。
- 活動達成の確認と対外公開の同意は**同じ親画面にあっても別の承認状態**。片方を押しても他方は処理されない。

## 操作の入口

| 役割 | 最初の画面 | 操作 |
|---|---|---|
| はる | 既存の子画面「今回のやってみ」 | 音声→本人の発言→AIの返答→短い提案理由→必要な比較カード→現実の行動→私的アルバムへ保存／任意の共有 |
| 保護者 | 今日の確認と件数 | 「確認する／アルバム／家族・特典」から、**共有内容・宛先**と**活動・ポイント**を独立に確認 |
| 祖母 | 家族の日付別新聞 | 許可された記事を読む、過去へ戻る、任意の返信、独立した「元気だよ」・歩数の手入力 |

### 保護者が一枚のカードで見るもの

1. はる本人が話した言葉（AIの言い換えと混同しない）
2. AIが提案した内容（**短い理由**・開閉できる出所と未確認）
3. 認める対象（共有：文章の該当版と宛先／活動：本人の実行報告と合意ポイント）
4. その場で行う主操作一つ、別の判断は別カードへ
5. 完了後の状態：「共有待ち→許可済み」と「実行申告→確認済み→ポイント確定」を別管理

### 本人の画面から取り入れたもの

- 大きな文字や装飾の模倣だけでなく、**会話→AI→説明理由→次の行動**の情報順序を親画面にも採用。
- 「AIが何を返したか」が親に見える。曖昧な能力評価や点数ではなく、**本人が選んだ理由・行動の記録**を見せる。
- 保存されていない／実行を報告していないのに、ポイント確認カードへ進ませない。
- 母・父の確認を毎回求めるのではなく、必要な確認が0件なら空状態を示す。

## スタンドアロン操作見本

2026-10-08版の **`やってみクエスト_子ども_保護者_祖母_統合UI.html`** は、会話とリーズニングが充実した子どもデモを保ったまま、「保護者」の3タブと祖母の新聞を同じ一時状態で接続したレビュー用ファイル。**この文書の追加だけではGitHub上の旧 `family-loop-demo.html` は変更されない**。配布HTMLとGitHub旧デモを混同しない。

実ブラウザー上で3役割の切替、はるの自由文入力・AIの模擬返答と根拠、保護者の共有再同意、祖母の記事閲覧・近況、40Pの二重付与防止を確認。320/390/768pxの全13ターンで上下の入力欄が重ならないことを確認。なお実音声・本番認証／配信・保存永続化は未実装。

### 依然未解決の事業仮説

親が実際に記事共有と活動確認を継続するか、祖母が読みたいと思うかは未検証。親は同一画面になっても、通知や承認頻度が高ければ離脱する。親の確認件数と処理時間を家庭PoCで測る必要がある。
