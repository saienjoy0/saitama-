### 2. 見せる体験とビジュアル

デザインの核は「家族の暮らしが冒険になる」。子どもは探索する見取り図と選択に応じた小さな反応、親は情報を絞った承認受信箱、祖父母は大きな文字のおたより。三者で色・用語・状態アイコンをそろえ、情報密度と最初の操作は変える。子どもを楽しませるのは意味ある発見・予想・比較・自分の理由と小さなアニメーションであり、連続ログイン報酬や能力採点ではない。発表用の「役割プレビュー／最初から」操作は発表者用バーにまとめ、実際の認証機能に見せかけない。

題材は架空の「300円で飲み物を選ぶ」に一本化。子どもが予想→A（180円/200ml）・B（260円/400ml）・買わないの比較→本人の選択→自分の理由→発見カードを作る。Aは支払額が安く残り120円、Bは100ml当たり65円で残り40円（Aは90円/100ml）。正解をAIが決めない。「どう比べたらよい？」で困った時だけ、確認済みの手順IDと文章から「お金を確かめる→値段と量を比べる→理由をつけて選ぶ」の模擬提案を提示。子どもが「もっと小さく／ヒントを見る／自分で進む／やめる」を選べる。固定ヒントと「AIによる手順提案の表示例（模擬・API通信なし）」を見分けられるようにし、疑似ロードや実通信を装う演出はしない。AIを使わなくても完走できる。

発見カードの内容・共有先を子どもが確認して「共有する／しない」。共有を断れば親にも祖父母にも表示しない。共有した時だけ親の受信箱に同じ版が表示され、親が内容・宛先を見て「承認／保留」を操作する。保留は祖父母に非表示。承認すると初めて祖父母へ届き、祖父母は「経験を伝える／質問する／応援する／返信しない」を自由に選べる。返信があれば出所付きで子どもに届き、なくても子どもは次の問いを自分で選べる。新しい問いを選ぶと、次の一歩が画面に現れるところまで接続。トーストでつながったように見せず、共通の一時状態が実際に変化するように作る。祖父母の元気や健康は推定しない。

必要な初期・保留・無返信・非共有状態を用意し、ダミーの「準備中」ボタンを主導線に置かない。意味不明な「成長率72%」や教育効果を示す数値は削除。子/親は16px以上、祖父母は20px以上を基本とし、タッチ領域48px以上、祖父母の主操作56px以上を目安に。控えめな遷移・明快なフィードバック、`prefers-reduced-motion`、キーボード操作、十分な対比、PCの16:9投影と390pxのスマホ幅に対応する。

### 3. デモとして正直に伝えること

全画面で控えめに「架空データ・発表用デモ／外部への保存・送信・実AI通信なし」を確認できるようにする。メモリ上だけで一巡を演じ、リロード・リセット時は最初に戻る。通信がないのに家族へ実際に届いたと言わない。AIの説明では「将来の仮説は、子の困りごとを監修済み手順に対応づける支援。今日はその表示例を操作している」と言えるようにする。実利用者の効果や継続率を証明した表現を作らない。

### 4. テスト、起動、発表準備

最小限で意味ある状態テストを用意し、少なくとも「共有しない」「共有→親が保留」「共有→承認→祖父母が返信」「共有→承認→無返信」の4分岐をブラウザで再現する。子の選択と理由が親の画面で一致し、未承認の記録が祖父母に現れず、リセットで全状態が消えることを確認。 `npm run build`、存在する型検査・テストも実行。Playwright/ブラウザが使えなければ、使用不能の事実と実際にできた検査だけを報告し、ブラウザ確認済みとは言わない。

`demo/presentation/README.md` にNode/npmでの起動・発表用ローカル表示方法、オフライン時の条件（依存インストール後にローカルで起動）、90〜120秒の台詞とクリック順、4分岐、リセット方法、模擬と未接続の境界を記載。発表用の画面キャプチャ一式をバックアップとして保存できるなら保存し、生成物の扱いをREADMEに明記。URL公開は今回の条件ではないので自動公開しない。最後に起動手順、完成画面、確認結果、残る制約、変更ファイルを簡潔に報告する。
