## プロンプト

あなたは `saienjoy0/saitama-` の発表用デモを完成させるCodexです。明日のプレゼンで、架空の一家を使い、子ども→親→祖父母→子どもの体験が90〜120秒で実際につながる、操作できるデモを作ってください。方針だけ返して止まらず、作成、動作確認、発表手順の記載まで実行してください。

作業開始時に最新版を確認し、`AGENTS.md` 指定順に状態・引き継ぎ・タスクを読む。`python3 scripts/check_design_handoff.py` を実行。特に `current/PROJECT_STATE.json`、`docs/design/personas-cycle-review-v0.4.md`、`docs/design/ai-engine-review-v0.4.1.md` と、リポジトリ内の `.agents/skills/yattemi-codex-workflow/SKILL.md`、`.agents/skills/yattemi-role-based-ui-design/SKILL.md`、`.agents/skills/gakusta-ui-prototype/SKILL.md`（`references/COMPONENTS.md` も）を直接読む。スキルの自動検出・外部プラグイン導入を前提にしない。現段階は DESIGN/D90。今回許可するのは `create_nonproduction_review_mockup` に当たる合成デモだけであり、BUILDへの段階移行、製品UI/API/DB実装、外部への公開、モデルへの実通信、実家庭データ処理はしない。他の作業者の差分は保護する。

既存の `prototype/gakusta/index.html` を出発点にする。画面の数を増やすより、次の同じ架空データが役割間で変化する一巡を最優先で実装する。クライアント内の一時的な状態だけで動かし、リロード時のリセットを明示する。ログインや本物の権限管理があるようには見せず、画面切替は「発表者用の役割プレビュー」と明記する。

1. 子ども：「300円で飲み物を選ぶ」例で、A＝180円・200ml、B＝260円・400ml、買わないも含め、予想→金額と量の比較→本人が選ぶ→理由を残す。180円と260円はいずれも予算内。Aは支払額が低く、Bは100mlあたり65円（Aは90円）なので、どちらかを自動的な正解にしない。実購入はしない。考えを小さな一歩に分ける補助を任意で開けるようにする。「いまの一歩」「もっと小さく」「ヒント」「自分で」「やめる」。固定の監修済み文言・手順IDから構成した表示例のみを使う。
2. AIの見せ方：「AIによる手順提案の表示例（模擬・API通信なし）」と画面内で正直に表示し、固定ヒントとは見分けられるようにする。例：「使えるお金を確かめる→値段と量を比べる→理由をつけて選ぶ」。困りごとから手順を選ぶUIにし、AIが答え・評価・共有先を決めない。模擬のためローディングや「いまAIが考えています」など実通信に見える演出はしない。AI補助なしでも最後まで進める。
3. 子どもが発見記録を見て「共有する／共有しない」を自分で選ぶ。共有しなければ親と祖父母の受信欄に現れない。共有した時だけ親の承認待ちに入る。
4. 親：実際に子が選んだ内容・理由・宛先・公開される文章を一画面で確認し、「承認／保留」を操作できる。承認したその版だけが祖父母の画面に届く。保留なら祖父母には届かない。トーストだけで済ませない。
5. 祖父母：承認された発見を大きな文字で読み、「昔の経験／質問／応援」から任意で返信するか、返信せず閉じられる。返信があれば出所を明示して子の画面に反映。返信がなくても子は進める。写真・健康状態・毎日の返信の催促をデモに足さない。
6. 子ども：返信を読んで次に比べたいこと（例：同じ量で値段を比べる）を自分で選べる。返信がなくても同じ選択へ進める。次の行動の選択が見えるところまで示す。

三者は共通の色・用語・状態表示を使うが、画面は目的別に変える。子どもは「暮らしの探検帳」のように興味が湧き、押した結果が楽しい控えめな動きで分かる体験にする。装飾や得点より選ぶ楽しさを優先。親は短時間で判断できる承認受信箱、祖父母は読みやすいおたより。投影するPC幅とスマートフォン幅の両方で読めること、キーボード操作、文字のコントラスト、`prefers-reduced-motion` に対応。根拠のない「能力72%」や学習効果の数値は表示しない。常時「架空データの発表用デモ／保存・送信・実AI通信なし」を見える位置に置く。

発表者がワンクリックで最初の状態に戻せるようにする。次の分岐を実操作で確認する：共有しない、共有→保留、共有→承認→祖父母返信、共有→承認→無返信。戻る/再操作で他人の未承認データが見えないこと。無効なボタンや「準備中」トーストを主導線に残さない。時間が厳しい場合はこの一巡の完成を優先し、新機能や本番構成は増やさない。

成果物：既存HTMLの改善、`prototype/gakusta/README.md` に起動方法（ローカル、オフライン可）、発表者の90〜120秒の台詞とクリック順、模擬である部分と未接続の部分、切り戻し方法を書く。画像や外部フォントはネットなしでも成立させる。可能なら実ブラウザでPC/スマホ幅と4分岐を確認し、使えない場合はその事実と実行できた代替検査を正確に報告する。合成デモの確認を製品の安全性・教育効果の検証済みと呼ばない。最後に変更ファイル、確認結果、発表時に必要な機材/接続、残る制約を短く報告する。
