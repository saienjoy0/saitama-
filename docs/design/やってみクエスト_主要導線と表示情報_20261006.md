# やってみクエスト｜主要導線と表示情報 v2
作成日：2026年10月6日  
状態：機能全体の提案に続く画面・導線の設計案。記録と共有を一つのカードへ整理した改訂。画面数は確定していない。製品実装、実送信、利用者観察は未実施。

## 1. この案で具体化すること
小学5〜6年生の買い物と、祖父母自身の近況を、同じ家族の記録へつなげる。見た目の仕上げに先立ち、表示する情報・主な操作・次の行き先・保存と公開の状態を定義する。

買い物では、前に条件を決め、後に短く記録する。比較・計算・知識の支援は本人が困った時に開く。現実の買い物の間、アプリの手順を消化する体験にはしない。

WF番号は今回の場面の番号。既存C/P/G番号は画面型、F番号は機能の参照。WF一件ごとに独立画面を新設する意味ではない。

### 1.1 シンプルにする中心案
**一つの出来事を、一つのカードで進める。話した内容は一度確かめて残し、共有を希望した分だけ親が確認する。許可された内容を、新聞とアルバムで読み返せる。**

毎回の記録・共有・新聞のために同じ内容を入力し直さない。比較や振り返りは、実際の生活で必要になった時に使える。全ての項目を順番に埋める手順にはしない。

| 役割 | 普段の入口と用事 | 主な導線 | 初めて価値が伝わる場面 |
|---|---|---|---|
| 子ども | 「今回のやってみ」。現実の選択を進め、残したいことを残す | 条件を決める → 実際にやってみる → 話して、同じカードで確かめて保存 | 自分が選んだことを自分の言葉で残せる |
| 親 | 「確認」と「家族の記録」。必要な判断と、子・祖父母の日常を知る | 確認が必要なカードを読む → 内容と相手を見て送る | 教材や新聞を一から作らず、本人の選択が分かる |
| 祖父母 | 「家族の新聞」。読む、自分の今日を届ける、過去を見る | 新聞を読む／見せる相手を確かめて近況を送る | 家族の出来事を読める・自分の近況が届く |

想定する場面は、子は買い物前後の家や店、親は準備・家事の合間、祖父母は自分が読みたい・残したい時。端末や音声入力への慣れは未確認。子の「毎回質問されるのは面倒」、親の「確認が積み上がる」、祖父母の「どこを押すと送られるか分からない」を設計上の懸念とし、実際に観察された感情とは扱わない。

### 1.4 初回だけ決めること、毎回見せること
家族の作成・招待・役割設定は管理する親の初回操作へまとめる。子の記録を本人と管理する親が見られること、祖父母への共有は任意であることを説明する。祖父母の参加を、子の最初の体験の開始条件にしない。

| 初回に設定すること | 毎回の扱い |
|---|---|
| 役割、誰と同じ家族か、記録の見える範囲 | 同じ役割の入口へ直接戻る。変更は設定でできる |
| 共有先の候補 | 前回の相手を候補として再利用し、名前を表示。新しい子の素材の共有意思は毎回選ぶ |
| 文字の大きさ、音声入力の希望 | 使える入力方法を維持。音声の権限は初めて使う時に確認 |
| 通知の希望 | 毎日入力するための通知を初期の必須導線にしない |

子のホームは前の出来事を続ける入口と、新しい用事を始める入口を示す。過去の比較・記録は「これまで」に置く。親は確認対象がなければ「確認はありません」と家族の記録を見せる。祖父母は新着の有無で「読む」「今日を送る」の位置を入れ替えず、同じ場所から使えるようにする。

「話す・確認して確定」の二つの場面は残る。音声の開始・終了や誤認識の修正を含む実際のタップ数、時間は未測定。操作の数だけでなく、読み直し・修正・親との引き継ぎまでの総負担で見直す。

## 2. 買い物の導線
全て架空の例。商品・価格・会話は利用者の実話ではない。

| 場面 | 画面で先に見せる情報 | 主な操作 | その他にできること | 押した後・記録の状態 |
|---|---|---|---|---|
| WF01 条件を決める | 今日の夕飯の材料／3人分／買い足す予算1,000円。使う日と家にある材料は必要な時だけ | この条件で始める | 条件を変える、今日はしない | 今回の条件が残る。親と子が確認した範囲で開始 |
| WF02 買い物を進める | 今回の目的と条件。続きの案内は短く表示 | 必要なときに助けを見る | 予算や予定の変更を相談する、中断 | 買い物は現実で進める。途中の入力は任意 |
| WF03 困り所を助ける | 「計算」「比べる点」「言葉や仕組み」等から本人が選んだ困り所に合う短い説明・例 | この助けを使う | 別の助けを見る、自分で続ける | 本人の比較・選択へ戻る。選択や理由を代筆しない |
| WF04〜06 記録カード | まず今回の用事と音声入力。話した後は認識した本人の言葉、金額等、見える相手、任意の共有希望 | 入力時は「話して残す」。確認時は「この内容で残す」。共有を選んだ場合は「保存して親に確認を頼む」 | 一言で書く、直す、写真を付ける、共有する相手と素材を選ぶ、後で | 同じカード上で入力・確認・共有希望を扱う。保存済みと、共有の確認待ちを区別して表示 |
| WF07 親が確認する | 今回の内容、子の言葉、写真があれば写真、宛先。文章の変更があれば原文との差分 | この内容を送る | 内容を直す、今回は送らない、後で確認 | 確認した内容と相手へ公開。体験の記録と共有の完了を別に扱う |
| WF08 家族が読む | 日付、投稿者、写真・本人の言葉。詳細な学習記録や家計の額は、共有に選ばれた場合だけ | 記事を読む | 読んだよ、経験・質問・応援を返す | 返事なしでも読書・体験は成立 |
| WF09 次の機会へ戻る | 前回の記録と「今は何をしたい？」。続きと新しい目的を選べる | 今回の目的を選ぶ | 前の記録を見る、別のこと、今は使わない | 新しい条件で開始。必要なら前の比べ方を参照 |

WF01の条件カードと、WF04〜06の記録カードが前後の基本。WF03は困った時に同じ出来事から開いて戻る。WF06の共有希望は記録カード内の任意の選択で、最初は選ばれていない。後日、保存済みカードから共有を選ぶこともできる。記録しない選択も残す。

登録時に、子どもの記録は本人と管理する親が見られることを伝える。祖父母に見せない選択と、管理する親にも見せない秘密の日記は混同しない。

### 最初の記録の例
本人が音声で次のように話した場合：

> 肉は少ない方にした。今日は使う分だけでよかったから。全部で860円だった。

| 項目 | 記録案 |
|---|---|
| 選んだこと | 本人の言葉「肉は少ない方にした」 |
| 理由 | 本人の言葉「今日は使う分だけでよかったから」 |
| 使ったお金 | 本人が話した860円 |
| 比較した商品・量 | 未記録 |
| 使ってみた結果 | 未記録。後で残せる |
| 助け | アプリのヒント利用は操作記録。親の助けは申告がなければ未記録 |

本人が話していない比較、理由、満足、理解を埋めない。未記録の項目を埋めるために、毎回追加質問を要求しない。860円に収まったことだけで、判断が良かったと判定しない。

### 記録カードの見せ方
以下は架空の内容を使った情報の見本。画面デザインや実際の保存機能ではない。

> **今日の買い物**  
> 夕飯の材料・3人分・予算1,000円  
> **話したこと**  
> 「肉は少ない方にした。今日は使う分だけでよかったから。全部で860円だった。」  
> **この記録を見る人：自分と、管理する親**  
> **家族にも見せたい：未選択**  
> 主なボタン：**この内容で残す**  
> その他：言葉を直す／写真を付ける／後で

共有希望を選ぶと、この場所に共有する本文・写真と、相手の名前を追加して見せる。共有候補として前回の相手を使えても、今回の素材を送る意思は新しく選ぶ。主なボタンを「保存して親に確認を頼む」に変え、「今は相手には届きません」と示す。別の共有画面へ進んで同じ文章を作り直さない。

共有候補は本人の言葉と本人が選ぶ素材を中心にする。家庭の予算・支援履歴・詳細な金額欄は初期の共有素材に含めない。**本文中に金額がある場合も、その本文を選べば共有される**ため、実際に送る文章を表示する。金額を外したい場合は子が引用する範囲を選び直し、その文章を確認する。AIが無断で言い換えて本人の発言として扱わない。

日付等の自動入力は直せる。記録項目の一覧は詳細から見られ、未記録の項目を毎回先頭に並べない。何をした・買わなかった・待つことにした、という本人の一言だけでも残せる。結果を追記するのは、実際に使った時や次の用事で役立つ時。追加質問は断れる。

保存が成功したらカードを「保存済み」にし、ここで終われる。共有希望がある場合は同じカードに「親の確認待ち」を表示。送信完了までアプリを開いたまま待つ必要はない。

### 音声・AI・通常処理の分担
| 作業 | 役割 |
|---|---|
| 話した内容を文字にする | 音声入力。本人が認識結果を直せる |
| 原文の引用・金額を記録項目へ整理する | 原文との対応が分かる記録補助。方式は別途選定 |
| 残額の計算、保存状態、許可された相手への表示 | 通常の処理 |
| 困り所に合う説明や例を出す | 最初は確認済みの支援。AIの候補対応付けは比較対象 |
| 新しい文章で短文化・説明する | 親向けの下書き。原文と比べて確認してから共有 |
| 何を選ぶ、誰に見せる、予算を変える | 本人・親の判断 |

音声入力の認識、記録項目の整理、新しい文章の生成を一つの「AIが全部やる機能」として説明しない。記録補助の原文引用と数字抽出は、今後の仕様で扱う出力・確認方法を明確にする。現行のAI契約に新しいjobが実装済みという意味ではない。

## 3. 親に何を見せるか
親の入口は「確認」と「家族の記録」。確認が必要なカードを先に示し、子の記録と祖父母等の近況へ移れる構成案。通知がある時は対象のカードへ直接入れる。確認待ちを読むためのメニュー選択を重ねない。

共有カードに、送る文章・写真・相手の名前を最初から表示する。親が押す主なボタンは「この内容を送る」。通常の文面で、さらに「よろしいですか」を繰り返さない。原文は同じカードで見られ、AI等で文章が変わっている場合は差分を必ず開いて見せる。未変更の長い補助情報は必要時に開く。確認済みの素材を同じ相手に見せるための新聞編集を、毎日必須にしない。

自動化する対象は内容・宛先・日付・下書きを揃える準備。新しい子の素材の公開は親の一押しで確定する。既に許可された固定の支援や記録保存は、この承認待ちに入れない。確認を省く目的で、子の新しい公開を自動で行う方式へ変更しない。

| 親が来た目的 | 最初に見せるもの | 親の操作 |
|---|---|---|
| 判断が必要 | 何を変える／何を誰に送るか | 内容に合った一押しの確認 |
| 子の今回を知る | 目的、選択、本人が残した理由、結果、助けの出所 | 記録を読む。返事は任意 |
| 以前と比べる | 関連する前回の記録と今回の記録 | 二つを見る |
| 家族の日常を知る | 本人が送った日付・一言・歩数等 | 読む。気が向けば返す |

成長の表示案：
- 前回：量を比べるヒントを開いた。
- 今回：本人の記録に「量を比べた」がある。
- 親の助け：未記録／本人か親が申告した内容。

出所の違う情報はそのまま区別して見せる。この二件だけで「自立した」「金融力が上がった」と認定しない。記録が不足している時は、比較できる情報がまだ少ないと示す。

共有確認で親が意味・素材・宛先を変更したら、変更後の内容を子に示して選び直す。変更前の共有意思と承認を使って送らない。事前に合意した条件内の体験や通常の保存は、毎回の親承認待ちにしない。

## 4. 祖父母自身の近況の導線
子の学習や家族の返事を待たず、自分の用事として使える。

| 場面 | 先に見せる情報 | 主な操作 | その他にできること | 押した後・記録の状態 |
|---|---|---|---|---|
| WF10 祖父母の入口 | 家族の新聞を直接開く。日付と名前、新着、固定位置の「今日を送る」「これまで」 | 記事を読む | 今日を送る、過去を見る、後で見る | 新着の有無で入口の位置を変えない。新着なしでも過去を読める |
| WF11〜12 今日の近況カード | 今日の日付と相手の名前。元気だよ／歩数／一言・写真は残したい分だけ | 「元気だよ」だけなら「『元気だよ』を送る」。書いた内容がある時は「この内容を送る」 | 内容や相手を直す、自分の記録に残す、後で | 本文・数値・宛先を同じ場所で見て送る。成人本人の投稿は本人の操作で公開。子世代の承認待ちにしない |
| WF13 日付別に読む・見返す | 許可された家族の出来事、日付、投稿者。最新から過去へ移れる | 見たい日を開く | 今日へ戻る、投稿者で絞る | 読み位置を保ち、過去の日の記録を見る |

「元気だよ」だけの時は、今日の日付、送る文言、相手が見えていれば送信を一押しで行える設計案。押した後に送信結果を表示し、取り消しの入口を残す。歩数や一言を入力する時も、追加の確認画面を必須にせず、送信ボタンの直前に内容を見せる。音声認識は本人が確かめて直せる。送信成功を相手の閲覧・返信と同じ扱いにしない。

日付別に読む、過去の自分の記録を見る、家族の出来事を見る、という入口から同じ許可済み素材を再利用する。投稿者と日付を保つ。自分の近況は任意で、空白の日から体調や安全を推定しない。現在の近況の表示期間と、本人の出来事をアルバムとして残す期間は別途整理する。

架空例：「今日5,200歩。公園まで歩いてきた」。歩数の取得元が手入力なら手入力と表示する。自動取得を使う場合は、どの機器・アプリから、いつ取得した値かを示す。取得方式・端末対応はまだ選定していない。

成人が自分の出来事を投稿する経路と、子どもの写真・言葉を共有する経路は区別する。祖父母の投稿に子どもの素材を含める場合は、本人と管理する親の共有確認に戻す。

### 日付別の新聞と、発行する新聞
- 日付別の閲覧：その相手に共有された出来事を、日付ごとに読む。
- 新聞の発行：選んだ記事と宛先を確認して、一つの号として出す。
- 許可済み素材を同じ相手が日付順に読む際に、親の再承認を毎回要求しない。
- 新しい素材や宛先へ共有する時の確認は維持する。
- 投稿がない日も、過去の記録を開ける。空の出来事を作って埋めない。

この区別で、毎日読む使い方と、親の毎日の編集作業を結び付けない。最新の近況と、本人が思い出として残す記録の保持条件は、次の仕様改訂で整理する。

## 5. 止まった時の情報と操作
| 状態 | 表示すること | 続け方 |
|---|---|---|
| 音声を使えない・認識が違う | 文字で残す入口、認識した原文 | 修正して保存、短文・ボタンへ |
| 理由や結果を残したくない | 残した項目だけの記録 | そのまま残す、後日追記 |
| 保存に失敗 | 未保存。入力内容は消さない | 再試行、後で続ける |
| 親の確認待ち | 記録は保存済み、共有は確認待ち | 他の体験・自分の記録は使える |
| 予算や目的が変わる | 前の条件と変えたい条件 | 親と相談、計画を変える、終える |
| 祖父母が返事をしない | 返信なし | 本人の目的から次へ進める |
| 家族の投稿がない | 新しい出来事はまだない | 過去を見る、自分で残す |
| 歩数を取得できない | 歩数は未取得。取得できたと見せない | 一言・元気ボタン、本人による手入力 |
| 送信に失敗 | 未送信。成功の表示をしない | 内容を保持して再試行 |
| 内容・相手が変わる | 変更された内容・宛先 | 対象版の選び直しと確認 |
| AIが使えない | 固定の支援・原文の記録を使える | 同じ目的で続ける、相談する、中断 |
| 共有を撤回する | 閲覧を停止した対象 | 自分の記録を扱う。印刷等の外部コピーも消せたとは表示しない |

文字を拡大しても主要情報と操作が使えること、音声以外の入力、戻る・中断、動きを減らした同じ情報の表示を、初期の設計に含める。

## 6. 既存仕様との対応と次の確認
| 場面 | 既存の画面・機能 | 今回の具体化 |
|---|---|---|
| WF01〜03 | C01・C02／F03〜05・F18 | 買い物の条件と、必要時に開く支援 |
| WF04〜06 | C03・C04／F06〜08 | 声の原文、記録項目、本人の保存・共有選択 |
| WF07 | P02／F09 | 内容・原文・宛先と一押し確認 |
| WF08〜09 | G01・G02・C01・P03／F07・F10〜12 | 家族の読書と、次の生活機会での再開 |
| WF10〜12 | G01・G04／F06・F13＋歩数の追加案 | 祖父母本人の生活記録と宛先確認 |
| WF13 | G02・P03／F07・F10＋日付別の追加案 | 日付で読み返す、最新の近況と過去の出来事 |
| 状態・例外 | F15・F16・F19・F20 | 失敗・保留・変更・撤回・入力の代替 |

文面上の確認では、非共有の子の体験、確認待ち、祖父母不参加、成人本人の投稿、音声・AI・通信が使えない場合にも、次の操作を定義した。実際の理解・操作時間・継続・学びは、まだ利用者に確認していない。

次は、この三者の主要導線を架空の内容で一巡できる簡単な見本へ落とす。豪華な見た目に先立って、表示内容と主なボタンを確かめる。機能の全体像と保存・公開・保留の状態を定義し、全機能の詳細画面を一度に作り込まない。

| 確認する場面 | 文面で定めた期待 | 利用者に確認すること |
|---|---|---|
| 子が記録して共有を選ばない | 保存で終わり、祖父母には届かない | 親には見えることを理解できるか、記録が面倒でないか |
| 子が家族にも見せたい | 同じカードで素材と相手を確認し、親の確認待ちになる | 既に送られたと誤解しないか |
| 親が共有を確認 | 本文・写真・宛先を一つのカードで見て送れる | 見落としや修正を含めて負担が少ないか |
| 親が内容・宛先を変える | 子の選び直しへ戻る | 状態と次の担当が分かるか |
| 祖父母が元気だよを送る | 内容・日付・宛先が見える場所で送れる | 保存するだけと送信することを区別できるか |
| 新着や返信がない | 過去を見られ、自分の用事を続けられる | 毎日参加する義務を感じないか |

文面の自己点検は、利用者の理解・学習効果・継続の証拠ではない。画面数やボタン数の削減だけを成果とせず、本人が判断できるか、誤認識を直せるか、家族の総作業時間が減るかを後で観察する。
