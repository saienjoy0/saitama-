# 親画面の見せ方｜確定仕様 v2（2026-10-08）

状態：**画面・情報設計の採用仕様。ユーザーテスト・実装・実運用の成功を意味しない。** 3シナリオは架空の例。Codexが作業中の子ども画面・祖父母画面を変更しない。旧「親画面｜子どもの『行動の過程』を理解できる 3シナリオ設計 v1」（PR #18）の、親向け画面構成とAI編集に関する章は本書を優先する。v1の競合調査と検証上の反例は引き継ぐ。

## 0. 一文で表す確定コンセプト

**子どもが現実に行動し、必要なときにAIと対話して残した「本人の経験」を、AIが出所付きの記事に編集する。親は「今日」で一瞬で近況と必要な確認を知り、興味があればその記事で経緯を読み、あとから親子のアルバムで同じ経験を振り返れる。祖父母には子ども本人の共有希望と保護者の承認がある版だけが新聞として届く。**

「詳しく見る」は別の何画面も移動するのでなく、**記事詳細の中で本文・根拠を必要なだけ読む**こと。

## 2. 親ホーム「今日」：最初に見える確定構成

下記は金額・時刻・文章・ポイントがすべて**架空の表示例**。

    ✦ やってみクエスト      今日
    ┌ はるちゃんから確認 1件 ─────────┐
    │ 夕飯づくりをしたと報告          │
    │ 40Pの実施確認待ち  [内容を確認 ›] │
    └───────────────────────┘

    はるちゃんの最近の出来事
    ┌ 🍛 おばあちゃんを迎える夕飯 ───┐
    │ 買い物と料理をしたと本人が報告   │
    │ 安い店と帰宅時間を比べて店を変更 │
    │       [どう考えたか読む ›]       │
    └───────────────────────┘

    家族の近況
    👵 おばあちゃん 今日12:06 元気だよ／5,200歩（手入力）
    👴 おじいちゃん 今日の連絡なし（前回の日時）

    [今日]  [アルバム]  [家族]

**情報の更新と空状態**
- 依頼なし→確認カードを出さない。最近の出来事がなければ「新しい記録はまだありません」だけ。
- 今日にすべての出来事を並べない。「最近の出来事」は最大1件、他はアルバムへ。
- 祖父母の「元気だよ」は本人の発信であり、健康や安全の客観的な保証ではない。未着・低歩数を自動異常判定しない。
- 頻出する時刻、受信ログ、長い注意文、報酬規約の全文はホームに常時表示しない。
- 依頼が複数なら件数と優先対象だけ表示し「確認一覧」へ。AIが勝手に承認の優先順位を決めない。
- 子の「報告」と親の「確認済み」を必ずラベルで区別する。
- 0Pや40Pは各家庭の事前合意に依存する架空例。20P・40P未確定の状態で50P交換済みの表示を作らない。

## 3. 詳細は「記事」：AIに構成を任せるが、重要な境界は固定

### 3.1 記事詳細の固定UI

常に同じ場所にあるもの：
- 戻る／日付／本人名／**記事の状態**（記録中、本人が保存、親確認待ち、親確認済、公開取り消し等）
- 題名と導入。最初の1〜2文で何が起きたか伝える
- **記事本文**（AIが今回の実際の内容から自然に編集、以下の可変部品を順序も含めて選択）
- 記事末の「実際に試したこと・確かめられたこと」と**確認状態・ポイント状態**を別表示
- 折りたたみ「**この話の元になった記録を見る**」：文と紐づく原発言、時点、報告者、証拠、確認状況
- 追加の固定操作：記事の訂正・共有状態の確認・前後の記事へ戻る（それぞれ権限に応じて）

**親は記事を開いたら十分な内容をその場で読める**。強制的に「ダイジェスト画面→タイムライン画面→全文画面」と移動しない。忙しい日には題名と導入だけで戻れる。

### 3.2 AIが毎回選ぶ記事の要素（固定テンプレートへの強制なし）

| 要素 | 使うべき時 | 誤った使い方 |
|---|---|---|
| 自然な文章 | 子の行動と経緯が記録されている | 事件の前後を推測で補い美談にする |
| 本人の言葉の引用 | 本人の発話原文がある | AIの要約を本人の発言に偽装 |
| 会話の場面 | 家族への相談・返答の記録がある | 子の伝聞を親が直接発言したことにする |
| 比較の表や図 | 同じ条件で比較可能な値・選択肢がある | 時間・値段・量の出所や時点を捏造 |
| 最初の案→考え直した案 | 以前と以後の本人の選択が残る | 単にAIが二案提示したことを「本人の成長」と呼ぶ |
| 失敗・試行錯誤の記録 | 失敗や中断、再挑戦の記録がある | 必ず前向きな成功物語に書き直す |
| 家族の約束 | 本人希望、親が確認した条件がある | 親の合意なしに「任せられる範囲」を増やす |
| 写真・本人の説明 | 本人が保存し、この用途で表示できる写真がある | 画像から気持ち・工程のすべてを断定 |
| 経緯の根拠 | 重要な主張がある | 元の記録を読めない長いAIだけの要約 |

AIは**見出し、情報の取捨選択、順序、文章量、可変部品**を決定してよい。UIのボタン、共有先、承認状態、ポイント、本人の出所表示、記事の保存状態はAI出力を鵜呑みにせずアプリ側が決める。モジュールは拡張できるが新しいHTML/JSをAIが直接実行しない。

### 3.3 AIの記事化と聞き取りの品質契約

- 自然な体験の途中で子が話した内容を重複質問しない。必要なとき子が戻って音声・短文・選択で話せる。**常時録音しない**。
- 具体的で重要な欠けがあるときは、その場の行動を妨げないタイミングで中立的に聞ける。「なぜA店にしたの？」は可。「お父さんのことを考えたからだよね？」は誘導になるので不可。
- **情報がなければ聞く義務はない**。記事を作るための質問攻めは避ける。未回答の部分は書かない。
- **AIが言った内容を子が言い直した場合も出所を区別**。先にAIが提示した根拠や候補を、子が自発的に発見したと書かない。
- 重要な文には元イベントID・原文／伝聞／AI補助／親確認の種別を内部的に紐づける。数字・発言・結果に根拠がない文は表示前に除外または本人へ確認。**モデルへの「嘘を書くな」指示だけで担保しない**。
- 公開前に子自身が記事を読んで「ここは違う」「この文章は載せない」「見せる先を変える」を修正できる。見せる相手と記事版が変われば共有意思・親承認を取り直す。
- 子の「料理した」の自己申告は**本人の報告**。親が実際に確認するまでは完了確定、能力向上認定、ポイント付与をしない。
- AIが使えなくても本人の短い原文と日付の記録を保存できる。生成記事だけを唯一の保存手段にしない。

### 3.4 プライバシー・親への閲覧

「子のアルバムに保存」と「親に見える」と「祖父母に公開」は別の操作・権限。子どもに**記録を始める前に、親へどこまで見えるか**を分かる言葉で説明する。親が実行・費用・安全を判断するのに必要な項目と、子が自由に下書きする相談・メモを区別する。

本稿では**親が見るのは、本人に明示した家庭記録と許可／達成確認に必要な情報**。生の音声履歴や非公開の自由メモを当然に親のトップへ表示しない。家計の全数字も記事へ自動転記しない。児童保護上の閲覧要件と具体的な本人・保護者同意画面は別の実装仕様で定義するまで、外部公開を進めない。

## 4. 3シナリオの実画面内容（すべて架空例）

**3本は表示の型を決める分類ではない**。その場の記録で中心が違えば同じシナリオでも異なる記事を作る。

### HSC-01「うちでは何を自分で決めていい？」— 初めての約束

ホーム：
- **「はるちゃんが夕飯を自分で考えたいと相談した」**。まだ親が約束を確認していなければ「約束の確認待ち」。0Pの例。料理完了とは呼ばない。

記事例：
- タイトル「『自分で決めてみたい』から始まった約束」
- 記録された本人希望を引用。「献立や買うものも考えたい」
- 親と相談した範囲が**親によって確認済の場合に限り**、記事内に「本人が考える：献立・買うもの／当日相談：人数・予算・店／一緒に：調理」と小さな約束表
- 子が「予算を超えたら料理を変えていい？」と質問した記録があれば、相談の山場として載せる。**なければ作らない**
- 何を次にやると本人が選んだかを末尾へ。まだ未実行なら「次にやりたいこと」であって結果ではない。

詳しく読む：希望→家庭への相談→子からの質問→親の回答の確認→今回決まった範囲。本人から聞いた親の回答は「本人の報告」と明示する。

### HSC-02「家は誰の仕事で回っている？」— 家庭の調査と一度の提案

ホーム：
- **「はるちゃんが買い物前の連絡方法を考え直し、試したと報告」**。20Pは約束済みの条件を親が確認するまでは確定しない。

記事例：
- タイトル「買い物の前に伝える、それだけで変わる？」
- 最初の理解「買い物と料理をすれば夕飯になる」→家族に聞いて「在庫確認、献立決め、帰宅前の買い物」も必要と知ったという**実際の本人発言があれば**載せる
- 本人案「家にある材料を伝える」→父の返答を聞いたと本人が報告「店に入ったあとでは遅い」→本人の修正「買い物に寄る日を聞いて、出発前に伝える」
- 最後に、実際に材料を確認して知らせたと**本人が報告**したこと。家計の年収・家族の支出は不要なら出さない。

詳しく読む：誰に何を聞いたか、どこで案が変わったか、初回の相談と実際に一度試した記録を分ける。

### HSC-03「おばあちゃんを迎える夕飯」— 価格・時間・家族への相談

ホーム：
- **「はるちゃんが買い物と料理をしたと報告」**。「60円安いB店も調べたけれど、迎えの時間からA店を選んだ」との本人の記録があれば一文。達成40Pの親確認待ち。

記事例：
- タイトル「60円安いお店より、大切になった条件」（**本人がその理由を語った場合に限る。そうでなければ中立な題名**）
- 今回の約束：4人・予算1,000円・16:45帰宅など（家族と実際に合意したと確認できる条件のみ）
- B店920円／A店980円。父が迎えられる時刻について父から聞いたという子の報告。**その後に本人がA店へ変更した記録があれば**「選び直し」を描く
- 店頭で肉400g520円と600g600円の比較が実際に記録されたなら別の小さな段落や図に。無ければ登場させない
- A店で買い物、帰宅、料理、食事を**本人が報告**した範囲で結末に。写真・レシートは任意。子からの報告だけで全部を親確認済にはしない。

詳しく読む：現物の在庫→チラシ比較→父への相談→条件と店の変更→売り場での追加判断→実行報告の**存在する節のみ**。子が一番力を入れた箇所が「迎えの交渉」なら会話を、料理の失敗なら試行錯誤を主役にしてよい。**価格比較表を必ず出すルールではない**。

## 5. アルバムと祖父母新聞：将来の読み返しまでが同じ価値

- **アルバムの1記事＝1回の出来事**を基本とし、途中なら続きが同じ出来事へ追記されるか別の日の続編記事になる。記事ID、版、出来事日時、記録日時を保存し、上書きで以前の時点の内容を無言で消さない。
- 一覧は年／月別、新しい順、題材、写真あり／なしから探せる。履歴が少ないとき検索UIは簡素に。親子が半年後・数年後も記事を開けることを想定するが、**保持年数・削除・端末移行は別途決める**。
- 過去と現在を比較するのは両方の記録に根拠がある時のみ。「昔は安さだけ、今は時間も考える」は本人が実際にその両時点でそう選んだ時だけ可能。能力や金融偏差値の推定には使わない。
- **記事を保存することと祖父母へ送ることは別**。子本人が共有する素材と相手を選び、保護者が同じ版を承認したものだけ祖父母の日付別新聞・アルバムに届く。新聞号としての編集・配達は任意で、親に毎日「発行」の義務を与えない。
- 過去記事は本人が原文を訂正できる。すでに公開済みの版は無断差し替えをしない。取り消し・公開先変更時は送信先で閲覧を止める設計とする。
- 成功した日だけを残さない。途中、中止、うまくいかなかった日も、本人の同意した言葉で記録が残ることが「新しい家族のアルバム」として重要。

## 6. 親の確認・ごほうびは記事と区別して扱う

| 状態 | ホームでの見せ方 | 記事内／別の確認画面で必要なこと |
|---|---|---|
| 実行前の許可 | 「献立と買い物を任せてほしい」 | 場所・移動・費用・誰と行くか・安全条件を親が確認。AIが承認しない |
| 本人からの実行報告 | 「買い物と料理をしたと報告」 | 合意した内容、本人の実行報告、親の確認。未確認のまま完了認定しない |
| ポイント確認待ち | 「40Pの実施確認待ち」 | 事前合意範囲の達成を親が判断。確認後のみ一度確定 |
| ごほうび申請 | 「カフェ50Pをお願いしたい」 | 残高と交換・予約状態・実費・いつ提供するかを別画面で確認 |
| 祖父母へ記事共有 | 「この記事を祖母に見せたい」 | 子の共有意思＋親が版・素材・宛先を確認 |
| 祖父母が読んだ／返信 | 今日の要確認には混ぜない | 家族の記録内に任意の返信として保存。子へ回答を強制しない |

確認操作はユーザーが**意思決定する専用UI**で行い、記事を読んだだけで自動承認しない。承認UIの詳細な操作と状態遷移は**別仕様（未確定）**。今回確定するのは親画面内の表示と入口まで。

## 7. 検証・受入条件（UX目標はまだ実証されていない）

1. 「今日」を開いて**3〜5秒**で親が「何の依頼がある／何をしたと本人が報告した／祖父母から連絡があったか」を区別できる（テスト目標、未測定）。
2. 子の最近の出来事を**1タップ**で記事として読める。記事内の根拠は必要時だけ開ける。アルバムからも同じ記事に1タップ。
3. 記事の3シナリオは**同じテンプレートの強制出力ではなく**、その回の発言・事実によって主体・構成が変わる。
4. 本人が理由を言わなければ理由を創作しない。AIが例示した理由を子の「自分で考えたこと」にしない。
5. 子の伝聞、原文、本人の報告、親の確認、写真証拠、AIヒントは区別する。記事内の中心的な断言には出所がある。
6. 未回答・写真なし・途中・中断・失敗・AI不調でも記録できる。記事を完成させるための追加質問義務はない。
7. 親の承認・ポイント確定・子の非公開保存・祖父母への公開は**別の状態**。記事生成で金銭と公開を動かさない。
8. 親子が記事を探し、過去の考えと経験を読み返せる。最初の記録を修正した際の版・削除・公開先の影響も説明できる。
9. 元発言が削除または公開範囲外になった場合、根拠のない要約をそのまま掲載し続けない。再編集または該当段落を非表示にする。
10. 身体・安全の保証、子の性格・能力点数、家計額の自動公開、未確認の行動の「できた」断定をしない。
