# 親専用「気づきレポート」× 家族新聞｜表示・AI質問・権限の契約 v3
2026-10-08／設計と操作可能な合成デモ。実家庭・本番AI・認証・実送信の実装ではない。

## 目的を分ける
| | 保護者向け気づきレポート | 家族新聞 |
|---|---|---|
| 用途 | 見ていなかった本人の選択、実際の工夫を知り、次にどう話すか考える | 思い出、本人の出来事と写真を家族で読み返す |
| 最初に見る | 今回の工夫、本人の言葉、必要な確認 | 出来事、写真、本人が共有した言葉 |
| AIの存在 | 記録済みの質問と回答がある場合のみ紹介／親への話題の提案（任意） | AIの質問理由、親専用の会話の提案は載せない |
| 公開 | 事前に説明した保護者閲覧権限 | 子の共有希望＋保護者の同一版・宛先・素材承認 |

**一件の出来事IDを共有**する。ただし公開権限、編集目的、表示位置は異なる。新聞のために本人が二重入力する必要はない。

## 親の画面：情報順
1. **「今日」**：判断を要する確認がある時だけ上部表示→新しい子どもの記事1件→祖父母自身の近況。重要な新着がない日は空の大カードを出さない。
2. **詳細記事**：親専用ラベルと現在の状態→「今回の工夫」一つ（説明1行・元イベントへのリンク）→「本人の言葉」（実記録がある場合）→「AIが実際に聞いたことと本人の返答」（両方のイベントがある場合に限る）→「親子で話せる一言」（新しい**AI提案**、任意に非表示）→「その後どうなったか／報告と確認の状態」→背景・元発言・新聞の編集見本を必要時に展開。
3. **アルバム**：初回の約束、家の仕事の調査、夕飯の実践の3体験について、同じ出所付き記事を再閲覧。従来の家族近況と親の確認デモは維持。
4. **家族新聞の編集見本**：記事内の独立折りたたみ。「未送信」の架空本文。親専用の行動評価やAI会話・問いは含めない。**見本を閲覧しただけでは公開にならない**。

## AIが質問した時の明確な条件
- 質問イベントID、本人の回答イベントIDの両方が存在し、保護者への閲覧権限がある時だけ、過去にAIが聞いたこととして表示。
- 「なぜこの質問？」を表示する場合、**質問前に記録された事実に基づく説明**であり、モデルの内部思考を表示するものではない。
- 新しく親へ提案する質問は「まだ子に聞いていない」と明記。親の質問義務・子どもの回答義務は発生しない。
- 記録されなかった子の感情、判断理由、父母の直接発言、行動結果を作文しない。子の伝聞、親の直接確認、AIから示された候補を区別。
- 子が記事化のための質問に答えない場合でも短い記録として成立。親の承認や報酬や新聞への公開とは切り離す。

## 3シナリオの編集差（すべて架空データ）
| 場面 | 親専用で伝える核 | 親に提案する任意の一問 | 家族新聞への編集見本 |
|---|---|---|---|
| 初回 HSC-01 | 「献立から決めたい」という希望と家族が合意した範囲 | 「やってみる日に家族に手伝ってほしいことは？」 | 初めて自分で決めたいと話した日 |
| 調査 HSC-02 | 店に入った後では遅いと聞き、出発前に材料を伝える案に変更 | 「先に材料を知らせたら何か変わった？」 | 家の仕事を知り、提案を試した日 |
| 夕飯 HSC-03 | 60円安い店と迎えの時間を比較し、A店を選んだとの本人の報告 | 「今度は最初に何を確かめたい？」 | 4人分のカレーを家族で準備した思い出 |

HSC-03のみ**質問／回答があった架空イベント**を追加して、AI質問の表示を確認できるようにした。他の二つのシナリオに実際にAIが聞いた記録は設定していないため、当該セクションは非表示。**元のプロジェクト資料にAIがその質問をした実績があるという意味ではない**。

## 固定操作とデータの安全性
- 今日／アルバム／家族という主ナビ、親の確認操作、報酬の残高／状態、本人共有希望・親の公開承認は通常コードで固定。AIが自由なHTML、認証、承認、送金、公開を出力しない。
- 実施を子が報告しただけでは40Pを確定しない。実施確認後も、祖母への新聞公開は**未承認のまま**。50P交換は独立。
- 本人・親がどこまで記録を閲覧できるかを、子が話す前に知らせることを本番前の未解決要件として扱う。
- 祖父母の「元気だよ」や歩数は本人の投稿・手入力であり健康や安否の保証ではない。
