# 実装用UIの共通ルール v2

2026-10-07。今日の機能整理v5と既存の三世代UI v0.3から、実装時の共通部分を定義する。[UI見直しと画面図v2](ui-review-20261007.md)で内容と状態の引継ぎを具体化した。ここでの見た目は初期方針。製品画面は今回実装しない。

## UIの方向
温かい家族の発見帳。生成画像は参考、[ui-system.json](ui-system.json)の意味と値を実装の基準にする。白いカード、温かい紙色、濃い緑の主操作、余白と読みやすい文字。子の選択、親の判断、祖父母の読書を中心にする。読書中の装飾は静かにする。

## 三者の入口
| 役割 | 普段の用事と入口 | 最初の場面・主操作 |
|---|---|---|
| 子ども | 今回のやってみ／これまで／お金とごほうび | 未完了なら続きへ。新しい用事では条件を見て「この条件で始める」 |
| 親 | 確認／家族の記録／設定 | 確認対象を直接読む。本文と相手を見て「この内容を送る」。0件は空の表示 |
| 祖父母 | 家族の新聞／今日を送る／これまで | 新聞を直接読む。読書には主ボタンを必須にしない。今日を送るでは内容と相手を見て「『元気だよ』を送る」 |

初回の家族設定は通常利用と分ける。タブは今日のv5を優先し、古いUI v0.3のタブ名を混ぜない。共有端末で見た目の役割変更だけで親権限へ進めない。

主操作は最大一つ。選択肢や通常の移動を消して一ボタンにする意味ではない。JSONのfirstActionは代表的な確定操作であり、ホームや読書で毎回強制する操作ではない。本文やナビは固定高で切らず、200%文字で必要なら縦に並べる。

## 共通部品と配置
実装先は `apps/web/src/design/`。各機能から部品へ依存し、部品が財布・公開・家族権限を書き換える責務は持たない。

| 部品 | 持つもの | 最初の用途 | 状態・確認 |
|---|---|---|---|
| ActionButton | primary/secondary、実行中、disabled、role size | S01〜S03 | 実行中の意味、キーボード、二重押下。色だけで状態を伝えない |
| Card / SectionHeading | 余白・階層・見出し構造 | S01/S02 | 200%文字と320px幅。内容を固定高で切らない |
| Field / FieldError | label、説明、値、エラーとの関連 | S02/S04 | 入力を失わず、その項目へ戻れる |
| StatusLabel | 状態コードと共通文言 | S04/S07/S08/S17 | 保存・共有・受取を別に示す |
| RecordCard | 原文、本人・日付、任意素材、出所 | S04〜S10 | 保存のみでも完了。共有した部分と見える人が分かる |
| AudienceSummary | 誰に何を見せるか | S07/S08/S10 | 実際の本文と名前。内容や相手の変更は対象版を再確認 |
| ReviewCard | 差分、根拠、宛先／変更条件、主操作 | S08/S17/S18 | 長い補助情報は必要時に開く。判断に必要な内容は初めから表示 |
| MoneyAmount | amountとunit、見込み／約束／受取の区別 | S13〜S22 | 円・P・練習円を別に表示。色やアイコンだけで単位を示さない |
| NewspaperArticle | 投稿日、投稿者、共有済み素材 | S09/S10 | 日付別・新着なし・撤回。自動ページ送りなし |

dialog等が初めて必要になった時はキーボードとfocus復帰を含めて一つの部品を採用する。今は複数の大型UIライブラリを重ねない。標準HTMLと共有CSS tokensを初期の基盤にする。

## 状態の整合
`recordState`・`shareState`・`redemptionState`は別の状態。保存済みで共有待ち、承認済みで未受取が成立する。JSONのstatesとlabelsを全画面で使う。UIのStatusLabelはサーバーの正規状態を表示し、animationendや見込みから成功を確定しない。交換の予約・差戻し・取消はS17のドメインが管理する。

## UI確認を各機能に組み込む
1. 同じ共通部品を使い、機能コードに色・余白・動きの定数を散らさない。
2. Storybookでその部品・用途の正常、空、実行中、失敗、保留・取消など必要な状態を並べる。存在しない状態は追加しない。
3. Testing Libraryでラベル・操作・状態、Playwrightで実ブラウザーの導線・二重操作・保存失敗を確認する。
4. 320/360/390/768px、文字200%、キーボード、focus、OSまたは本人の動き抑制を確認する。祖父母本文20px以上、主操作56px以上を保つ。
5. axe検査に加えて実際に読み・操作を確かめる。自動検査や画像だけで使いやすさや学習改善を認定しない。

部品のstoriesと検査は対象S機能と同時に作る。環境整備では製品部品・storiesを先行実装しない。

## 参照と適用
- 機能全体v5：入口・一件の記録・一機能ずつの完成。
- role-experience-v0.3：色、文字16/20px、タッチ48/56px、角丸16px、M01〜M07。
- 役割別UIスキル：同じ意味、役割ごとの情報量、一つの主操作。
- https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html ：本文4.5:1以上の確認。
- https://www.w3.org/WAI/WCAG22/Understanding/reflow.html ：狭い表示での読み進め方。
- https://storybook.js.org/docs/get-started/frameworks/react-vite ：React/Viteの部品の状態を独立して確認。
- https://playwright.dev/docs/browsers ：検査用ブラウザーをインストールし、実ブラウザーで確認。

参照した資料の事実と、この製品向けの値・構成を区別する。画像の配置や装飾は実装時に調整できる。
