更新日：2026年10月7日（Asia/Seoul）

対象：この会話で決めてきた本体機能と、その実装への引継ぎ。各機能を開発・確認・修正して次へ進む。ここにある区分は製品の画面数や、全機能を一度に作る単位ではない。

## 1. 今回の整理方針

**先に全体の枠をそろえ、これまでの詳細案をそこへ置く。その後は一機能ずつ、動作・保存・確認まで作って直し、次へ進む。**

最新のユーザー方針は「次は実装。今日決めたものを整理する」。本書を次の開発の入口とし、機能の担当範囲、接続、最小の完成条件をまとめる。実装期間や担当人数の実測がないため、日数・速度・達成率は置かない。

目指す変化：子どもが日常のお金について考え、比べ、選び、試せる範囲を広げる。その過程と家族の日常を記録に残し、親は次に何を任せるかを判断しやすくなる。初期対象は小学5〜6年生とその家庭。代表場面は親子で条件を相談する夕飯の買い物。

### 各機能の完成条件

#### S01 家族・役割・保存・共通の入口

利用者：全員。既存参照：F01・F02・F15・F16・F19・F20。担当領域：family / identity / ports / design。

- 家族と役割を切り替えても別家庭・親の情報を子へ返さない。
- 保存が失敗した時は未保存と表示し、再開しても入力を失わない。
- 文字拡大・音声以外の入力・戻る操作から同じ用事を続けられる。

#### S02 今回の用事・目的・条件

利用者：子・親。既存参照：F03・F04。担当領域：experience。

- 親子が決めた条件を表示し、変更・中断・再開できる。
- 買わない、待つ、別の用事にする選択を残す。
- 条件を決めることと、実際に使った額を記録することを分ける。

#### S03 比較・相談・必要時の支援

利用者：子。既存参照：F04・F05・F18。担当領域：experience / content。

- 本人が比べる条件と選択を変えられ、支援を閉じて自分で続けられる。
- 買うことや一番安い商品を自動で正解にしない。
- AIなしの固定の説明で用事を続けられる。商品検索・価格連携は別の拡張として扱う。

#### S04 一言・音声の記録カード

利用者：子・成人。既存参照：F06。担当領域：records / voice。

- 音声の認識結果を本人が直してから保存し、使えない時は文字に切り替えられる。
- 話していない理由・理解・感情を補って本人の言葉にしない。
- 保存済み・未保存を区別し、共有しなくてもここで終われる。

#### S05 写真を付ける

利用者：子・成人。既存参照：F06・F16。担当領域：records / media。

- 写真なしでも記録を保存できる。
- 許可された人だけが写真を取得でき、撤回した素材を再取得できない。
- アップロード失敗を保存成功と表示しない。位置情報とサイズは既存画像仕様に従う。

#### S06 アルバム・過去の出来事

利用者：全員・許可範囲。既存参照：F07。担当領域：records / album。

- 保存した一件を再入力せず一覧と詳細で読める。
- 原文・後日の追記・家族の言葉の出所を区別する。
- 私的な予算・支援履歴を、家族向けの表示へ自動で含めない。

#### S07 見せる内容・相手の選択

利用者：子。既存参照：F08・F15。担当領域：sharing。

- 共有の初期値は未選択で、見せない選択から終われる。
- 実際に送る文章と相手の名前を表示する。
- 変更・撤回に合わせて公開範囲を更新する。

#### S08 親の確認トレイ・一押し承認

利用者：親。既存参照：F09。担当領域：sharing / review。

- 何を誰に送るか見える状態で、一押しで確定できる。
- 内容や相手を変更したら、古い共有意思と承認を使わない。
- 日付・宛先候補・下書きの準備を自動化し、同じ確認を重ねない。

#### S09 家族新聞・日付別の閲覧

利用者：家族。既存参照：F10。担当領域：family-feed / sharing。

- 同じ許可済み記録を新聞とアルバムで使う。
- 毎日、親が編集して発行しなくても読める。
- 新着がない時も過去を読め、撤回した素材は表示しない。

#### S10 祖父母本人の「元気だよ」・一言

利用者：祖父母・成人。既存参照：F13・F06。担当領域：family / records。

- 成人本人の投稿は本人が確定し、子世代の承認待ちにしない。
- 送信の成功と相手の閲覧・返信を区別する。
- 未操作の日から健康や安全を判定せず、子の記録や学習も止めない。

#### S11 読んだよ・経験・質問

利用者：家族。既存参照：F11。担当領域：family / replies。

- 返信しなくても記事を読め、子の体験が終われる。
- 経験・質問・応援を事実や正解へ置き換えない。
- 元の共有が撤回された時の閲覧範囲を守る。

#### S12 家族の言葉から次のたね

利用者：子。既存参照：F12。担当領域：experience / family。

- 採用しない選択を残し、自動で体験を開始しない。
- 元の返信、本人の焦点、次の体験をたどれる。
- 元の返信が撤回されたら派生候補を見直す。

#### S13 円の受取・支出・残り・目標

利用者：子・親。既存参照：F14。担当領域：allowance。

- 入った・使った・残ったを整数円で記録する。
- 渡す予定・承認した追加額を受取済み残高へ先に加えない。
- 訂正は元の取引に対応する履歴を残す。

#### S14 金額・渡し方・用途の家庭設定

利用者：親・子。既存参照：F14。担当領域：allowance / rules。

- 親が選んだルールと次の受取予定を子が見られる。
- 周期と金額を別に変更でき、周期だけの変更で期間総額を混同しない。
- 変更の対象期間と版を残し、本人の希望を確認できる。

#### S15 家族ポイントの付与・残高

利用者：子・親。既存参照：今日の追加機能。担当領域：rewards / points。

- 円とポイントを別の残高と履歴で見せる。
- 付与と訂正を記録し、再試行・二重操作で二重付与しない。
- 記録・公開・毎日ログインや能力点をポイント獲得の義務にしない。

#### S16 家庭の特典一覧

利用者：子・親。既存参照：今日の追加機能。担当領域：rewards / catalog。

- 追加のお小遣い、プレゼント、お出かけ等を家庭が設定できる。
- 内容・対象期間・家族の負担を含む交換条件を示す。
- 全家庭共通のポイント換算やDisney等の提供をサービスが保証した表示にしない。

#### S17 交換・親確認・受取・取消

利用者：子・親。既存参照：今日の追加機能。担当領域：rewards / redemption。

- 申請時の予約、承認時の消費、実際の受取を別の状態にする。
- 親の確認トレイから内容と条件を見て判断できる。
- 却下・取消・提供不可では対応する返却を行い、二重消費・二重受取を防ぐ。

#### S18 根拠付きのお小遣い・任せ方提案

利用者：親・子。既存参照：F03・F04・F14。担当領域：responsibility。

- 対象領域、根拠となる記録、未確認点、提案条件を同じカードに示す。
- 記録不足では保留し、単一の能力点や全面的な自立認定へ変換しない。
- 親の承認と子の希望、試した後の見直しを残す。判定方式は透明なルールから始める案。

#### S19 家庭内金利・使う／貯める配分

利用者：子・親。既存参照：F14。担当領域：allowance / interest。

- 月率／年率、支払者、対象額、上限、未受取を示す。
- 途中の引出しとルールの版変更で対象額を再計算する。
- 増える見込み、支払の約束、受取済みを区別する。5%等の既存数値は説明例として扱う。

#### S20 銀行・預金の練習

利用者：子。既存参照：今日の追加機能。担当領域：finance-practice / bank。

- 練習円と実際の円を別に表示する。
- 選んだ配分と期間の結果を確かめられる。
- 練習が実際の銀行口座や円残高を動かさない。

#### S21 借りる・返す練習

利用者：子。既存参照：今日の追加機能。担当領域：finance-practice / borrowing。

- 受け取る額と返す総額を両方見せる。
- 借りない・待つ選択と、返済後の配分を扱う。
- 実際の借金・信用契約を作らない。

#### S22 銘柄・利回り・損失の練習

利用者：子。既存参照：今日の追加機能。担当領域：finance-practice / investment。

- 利回りの期間と損益を示し、利益だけを固定で出さない。
- 買わない・待つ・分ける選択を残す。
- 練習の値動きや損失を、家庭の実資金に連動させない。

#### S23 困り所に合う候補・手順の補助

利用者：子・親。既存参照：F18。担当領域：ai / experience。

- 固定の支援へ戻れ、本人が採用・変更・見送りできる。
- 候補の出所と表示理由を示し、モデルに公開・お金・権限の変更を任せない。
- 現行AI契約で許された入出力と提供条件を満たす時だけ使う。

#### S24 記録整理・新聞下書きの補助

利用者：本人・親。既存参照：F17。担当領域：ai / records / sharing。

- 原文と整理した項目の対応を示し、未発言の事実を埋めない。
- 新しい文章は下書きとして原文との差分を示し、確認した内容だけを共有する。
- 音声認識・通常の計算・AI生成を別の作業として扱う。新しい記録整理jobは既存契約への追加検討が必要。

#### S25 歩数などの近況記録

利用者：祖父母・成人。既存参照：F13。担当領域：family / activity。

- 取得元・取得時刻と手入力を区別する。
- 取得できない時も元気ボタン・一言を使える。
- 日々の数値や空白から健康の結論を出さない。

#### S26 日記としての利用

利用者：本人。既存参照：F06・F07。担当領域：records / diary。

- 金融の問いを必須にせず、記録する内容を本人が選ぶ。
- 管理する親に見える記録と、秘密の日記の公開範囲を明確にする。

#### S27 新聞の印刷

利用者：家族・許可範囲。既存参照：F21。担当領域：sharing / print。

- 印刷前にも対象素材と権限を確認する。
- 共有撤回で外部の紙まで回収できたと表示しない。

#### S28 機能をつないだ確認・運営記録

利用者：開発・運営。既存参照：F19・F20。担当領域：operations / tests。

- 保存・公開・金銭・受取を伴う変更に対応する検査を実行して証拠を残す。
- 返信なし・祖父母不参加・通信や音声やAIが使えない場合も主要な用事を続けられる。
- 操作できたこと、学習の改善、支払需要を別の成果として記録する。

## 6. 実装する順番と、一回の進め方

最初の順番は、**共通基盤 → 条件・比較・支援 → 記録 → アルバム → 共有選択・親確認 → 新聞・祖父母の近況 → 財布と家庭ルール → ポイント・特典・交換 → 任せ方・家庭内金利**。返信・次のたねは新聞の後に足せる。AI、歩数、日記、印刷、銀行・借入・投資の練習は各前提がそろった後に追加する。

一つの機能を進める時は、次の順番で行う。

1. 対象S番号、利用者、最小の完成条件、使う既存仕様を確認する。
2. 対象機能のファイルと入出力を決め、必要な保存・状態・権限を含めて実装する。
3. その機能を使い、完成条件と該当する失敗・変更・取消を確認する。
4. 修正を終えたら既存機能との接続を確認し、次のS番号へ進む。

機能の作業量が大きければ、同じ機能内で最小の用途を保った小さな単位に分ける。関連機能がそろったところで全体の導線を確認する。S番号の順番は依存と確認結果で見直せる。

準備済みのB10〜B70は実装管理の大きな区分として残し、その中をS番号ごとに開発・確認する。[実装計画](../superpowers/plans/2026-09-23-yattemi-implementation.md)に、担当ファイル・入出力・確認方法を対応付ける。
