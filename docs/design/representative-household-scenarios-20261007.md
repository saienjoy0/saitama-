# やってみクエスト｜行動を中心にした家庭の代表シナリオ3本

更新日：2026-10-07（Asia/Seoul）  
対象：本体製品 DESIGN／D90の設計追補。実装時の必読参照。  
状態：利用体験の設計案。製品実装・ライブAI・家庭観察・教育効果の実証ではない。

## 0. この文書の位置づけ

ユーザーの依頼は、開けば利用の流れを確認でき、後の実装がその体験を再現するためのシナリオを作ること。発表の台本、機能紹介、操作可能なデモを作る依頼ではない。

今回の方針：

> AIや検索で知識を得やすい時代に、子どもが必要なことを現実に調べ、人と話し、相談・交渉し、情報を使って判断して実際に行動する機会を作る。

3本は、同じ家庭の連続した代表場面とする。各1本でも開始から結果まで読める。

| ID | 役割 | 到達点 |
|---|---|---|
| HSC-01 | 初回設定 | 本人が希望を伝え、親子で任せる範囲を合意し、最初の挑戦を選ぶ |
| HSC-02 | 調査クエスト | 家の仕事とお金を調べ、理解を変え、自分の提案を一度試す |
| HSC-03 | 実践クエスト | 献立・予算・在庫・店・移動・家族の都合を調整し、一食を引き受ける |

家族、会話、料理、時間、価格、収入、ポイントはすべて合成の仮例。会話は想定台詞であり、実際の子どもに同じ答えや理由を言わせる仕様ではない。話されなかった理由・未実行の結果を、記録や記事で補わない。

最新のユーザー方針を利用体験の基準とする。既存のモデル入出力・同意・年齢・公開・報酬の契約を変更済みとは扱わない。旧仕様との差分と実装前の確認は第10節。

## 1. 3本に共通する設計原則

### 1.1 知識支援と行動代行を分ける

| AI／アプリが補助すること | 子どもが実際にすること |
|---|---|
| 知識、計算方法、料理や手順の候補を示す | 自分の目的を選び、家庭で使えるか確かめる |
| 調べる観点、情報源、聞き方の例を示す | 家族に聞く、実物を見る、チラシ・ウェブ・店で調べる |
| 集めた情報と条件の食い違いを整理する | 優先順位を決め、計画を選び直す |
| 依頼の要点や言い方を補助する | 本人が頼み、相手の返答を聞き、案を調整し、合意を確かめる |
| 本人の発言と確認された結果から過程の記事を作る | 現実に行動し、記事が自分の経験に合うか確認する |

AIに答えを言わせないこと自体を目的にしない。一般知識や計算をわざと隠さない。検索やAIで調べることも本人の調査に含む。調査のためだけに外出させない。一方、今日の在庫、家族の希望・都合、送迎への合意、実際に買った結果は一般知識から確定できない。

### 1.2 音声は行動を支える入口

- 子どもは必要な時に音声で相談・報告する。常時録音や、家族の会話の無断収集はしない。
- 一度の発言に複数の情報があれば、まとめて受け取る。項目ごとの聞き直しを要求しない。
- 調査や会話をしている間はアプリを閉じてよい。「見てきた」「聞いてきた」で同じ出来事に戻れる。
- 困っていない時は補助を開かず進められる。音声が使えなければ短文・選択でもよい。
- 知識不足には短い説明や具体例、事実不足には確認先、条件の衝突には選択肢の整理を出す。常に「なぜ？」で返さない。
- 各場面の記録欄は実装者向けの追跡項目。全部を本人に入力させたり、記事を完成させるために追加質問したりする要件ではない。

### 1.3 三者の用事

| 役割 | 用事・気になること・場面 | 最初に成立すべき行動 |
|---|---|---|
| 子 | 自分で献立と買い物を決めたい。長い入力や採点は嫌。家・店で短く使う | 希望を伝え、自分で次の一歩を選ぶ |
| 親 | 安全な範囲で任せたい。先生役と確認作業の増加が気になる。準備や家事の合間 | 条件を合意し、必要な相談に現実の都合を返す |
| 祖母 | 孫が何を考えたか読みたい。返信義務は持たない。好きな時に読む | 許可された記事を読む。参加・返信なしでも子の体験は成立 |

同じ出来事の記録を記事・新聞・アルバムへ再利用する。子の選択・共有意思、親の確認、モデル処理への同意を一つにしない。動きやゲーム演出は今回設計しない。将来付ける場合も既存M01〜M07／動き低減を維持し、行動・報酬・共有の成立条件にしない。

## 2. 共通の家庭

はる：小学5年生。父・母と3人暮らし。祖母は別居。買い物は頼まれた物を買う経験まで。献立から引き受けたことはない。

家の仕事は親双方にある。仮例の担当はこの家庭の現状であり、性別で固定した役割や望ましい分担を示すものではない。サービスが役割を割り当てない。

家庭の報酬は役割ごとに親子で合意する仮設定。初回0P、短い在庫確認10P、調査20P、一食の段取りと実行40P。サービスによる現金支給、1P＝1円、一般家庭の標準報酬を意味しない。

## 3. HSC-01｜初回設定「うちでは、何を自分でやってみられる？」

### 開始と知る必要

親子で初めて開く。はるは「夕飯を決めてみたい」が、何を決めてよいか分からない。必要なのは家族構成、今の仕事、経験、任せる範囲、相談先。家計全体の開示は初回に求めない。

### 代表場面

| 場面 | 子ども・家族の言葉と実際の動き | AI／アプリの補助 | 残すこと |
|---|---|---|---|
| 01-A 家族紹介 | 親子で暮らす人を紹介。祖母は別居と伝える | 暮らす人と、共有先候補を分けて整理 | 家族・関係。祖母の招待は開始条件にしない |
| 01-B 家の仕事を紹介 | AI「夕飯までに誰が何をする？」。子「母が料理、父も買い物」。母「在庫を見て献立も考える」。父「洗濯する日もある」 | 紹介された仕事を家のチーム表に並べる。未確認は空欄 | 家族の申告した現在の役割・出所 |
| 01-C 本人の希望 | 子「献立も買う物も自分で決めたい。今までは頼まれた物だけ買った」 | 希望と今の経験を整理。能力点は付けない | 本人の希望・経験 |
| 01-D 親子で範囲を相談 | 親「一食から。人数と予算はその日に相談。調理は一緒」。子「予算に入らなかったら料理を変えていい？」。親「人数と時間に合えばいい。変える時は教えて」 | 本人が決めること・親に確認すること・一緒にすることを短く示す | 合意した範囲。本人も内容を確かめる |
| 01-E 移動と助けを確認 | 親「店と道は家族で確認。荷物が難しそうなら先に相談」。子が困った時に頼む相手を確認 | 家庭ルールを保持。AIが勝手に行動許可を増やさない | 店・道・調理・相談の制約 |
| 01-F 最初の挑戦 | 子「いきなり全部は難しそう。まずご飯がどう決まるか知りたい」。調査クエストを選ぶ | 短い在庫確認／仕組みの調査／一食を引き受ける、の少数候補を提示 | 本人が選んだ最初の挑戦と次の一歩 |

親が答えるだけで登録を終えない。本人が希望を出し、分からない任せ方を聞き、範囲を合意することが中心。全部の家事をこの場で調べ切らず、気になった空欄は次の調査へ残す。

### 終了と変化

初回のまとめ例：

> はるは、頼まれた物を買うところから、献立と買う物を決めることへ挑戦したいと話しました。人数と予算はその日に家族と相談し、調理は一緒にする約束です。最初は、家の食事を支える仕事を調べます。

成果は「プロフィール完成」ではなく、希望・任せる範囲・最初の行動の合意。この例では0P。嫌な挑戦は選ばず、別の題材や後日開始にもできる。

## 4. HSC-02｜調査「この家は、誰のどんな仕事とお金で回っている？」

### 開始と知る必要

はるは「買い物して料理すれば夕飯はできる」と考えている。初回に献立決めも仕事と分かり、「父と母が買い物をしているのに、同じ物を買うことがあるのはなぜ？」と気になる。

一日の家を手がかりに、見える家事、見えにくい準備、収入と生活費の流れを調べる。全家計を網羅するクエストにはしない。親子で、調べて説明し一つ試す範囲と20Pを事前に合意する。

### 代表場面

| 場面 | 子どもが考え、現実にすること | AIの補助 | 家族とのやり取り・記録 |
|---|---|---|---|
| 02-A 今の考え | 子「買い物して、料理して、お金を払えばご飯ができる」 | 調べる前の考えとして残し、正解へ直さない | 本人の原文 |
| 02-B 調べる入口 | 誰に何を聞くか選び、家族へ聞きに行く | 食前・食後の仕事、担当、お金の出所という観点。困れば「今日、夕飯までに何をした？」の聞き方例 | アプリ外での質問。戻ってから話す |
| 02-C 仕事を調べる | 母へ在庫・献立・調理、父へ買い物・洗濯・片付けを聞く。実際の準備も見る | 得た情報を仕事のつながりとして整理 | 親双方の仕事、実物を見たこと、まだ未確認の仕事 |
| 02-D お金を調べる | 誰が働いて収入を得るか、何の生活費を誰が払うかを家族に聞く。見せられる家計の一部を確認 | 不明な言葉は短く説明。実際の金額や支払者は家族に確認する | 家族が話せる範囲だけ。給与明細の提出は求めない |
| 02-E 分かった範囲を区別 | 収入と一部支出の差を、全部自由に使えるお金と思いかける | 計算結果と、まだ集めていない支出を分ける | 他の支出があるか家族に聞く。未確認額は埋めない |
| 02-F 重複買いを確かめる | 玉ねぎを見て、買った人と買う物を決めた人へ、どう決めたか聞く | 「誰が悪いか」ではなく決め方と情報の流れへ戻す | 父「仕事帰りは在庫を見られない」。母「在庫を毎回伝えてはいない」 |
| 02-G 提案と調整 | 子「家にいる日は僕が在庫を見て伝えようか」。父「店に入った後では遅い」。子「寄る日は先に教えて。出かける前に伝える」 | 提案の要点を補助。毎日の担当に自動設定しない | 相手の都合を聞き、方法を調整した合意 |
| 02-H 一度試す | 米・玉ねぎ・にんじん・ルーを親と確認し、買い物前に伝える | 確認時点と使ってよい量を記録。次へ再利用 | 実際に確認・伝達した結果 |

02-D〜Eの金額は合成例：父の月の手取り30万円、母10万円。家賃10万円、先月の食費7万円、水道光熱費2万円。収入40万円、確認した支出19万円。

> 子「21万円は好きに使えるの？」  
> AI「今聞いた額の差は21万円。ただ、まだ聞いていない支出があるかもしれない。ほかに何に使っているか聞くと確かめられるよ」

親から通信費・交通費・将来のために残すお金などもあると聞く。差額を可処分額として確定しない。家計額は家庭内の確認に用いる情報で、外部AIへ送ってよい入力や家族新聞への公開を意味しない。

02-F〜Hの具体例：在庫は玉ねぎ3個、にんじん2本、米とルーは翌日の4人分に足りる。家族へ伝えるだけでなく、買う前に伝えるタイミングを合意して一度行う。担当の恒久固定や親への非難が学びの結論ではない。

### 記事・ポイント・変化

> **家は、料理を始める前から動いていた**  
> はるは、夕飯の前に在庫確認や献立決めがあることを家族に聞きました。玉ねぎの買い足しを調べると、確認する人と買う人が同じ情報を持っていないことがありました。はるは、家にいる日に買い物前の在庫を伝える方法を提案。父の都合を聞いてタイミングを決め、翌日の材料を確認して伝えました。

本人が言えば「料理の前にも仕事があった」「買う人に先に伝えればよい」を原文として残せる。言っていなければ本人の学びとして作らない。

親が合意した調査・説明・試行を確認すると20P。家計の全数字を集めた数や質問回数で加点しない。記事作成・祖母への共有は達成条件にしない。

## 5. HSC-03｜実践「おばあちゃんを迎える夕飯を、段取りから引き受ける」

### 開始と知る必要

祖母が夕飯に来る。はるが献立と買い物を考えたいと申し出る。前の調査の在庫記録が使えるが、その後使われていないかは確認する。

| 条件 | 今回の合意 |
|---|---|
| 人数 | 4人。祖母は来訪者であり同居者ではない |
| 食事 | 17時30分。買い物から16時45分までに帰宅 |
| 食材費 | 家庭のお金から買い足す予算1,000円 |
| 店・道 | 親と確認したA店／B店と経路。今回は行きは歩ける |
| 調理 | 親と一緒。家庭で決めた工程を本人が担当 |
| 任せる範囲 | 献立、必要量・在庫、店・商品選び、移動の相談、買い物、調理 |
| 達成と報酬 | 合意した範囲を実行。変更が必要なら家族と相談。事前合意40P |

家庭の食材費と本人のお小遣い・ポイントは別。完璧な判断、最安値、助けなし、写真や新聞の完成を達成条件にしない。

### 05-A 献立を決める

> 子「何を作ればいいか分からない」  
> AI「昨日確認した米、玉ねぎ、にんじん、ルーは今日も使える？ 使えるならカレーは買い足す物を少なくできそう」  
> 子（実際に見て戻る）「まだある。カレーにする。おばあちゃんが好きなトマトも出したい」

何も思いつかない時は少数の料理候補と必要な材料を説明してよい。候補を選ぶことを正解扱いせず、別の料理にもできる。祖母の好みは本人・家族から得た情報として扱う。

### 05-B 人数・必要量・在庫を確かめる

家で使うレシピやルーの表示を親と確認。今回の計画は肉400g、じゃがいも、トマトを買う。米・玉ねぎ・にんじん・ルーは家にある。レシピの必要量をAIの思いつきで確定しない。献立の材料一覧と、買い足す物を分ける。

> 子「4人分。家の材料を使って、肉400gとじゃがいもとトマトを買う」

AI／アプリが同じ出来事へ整理する。既に伝えた人数・予算の再入力を要求しない。

### 05-C 店の情報を調べる

> 子「どのスーパーが安い？」  
> AI「家族が使う2店の今日のチラシで、買う物の値段を確かめられるよ。同じ量で比べよう」

本人がチラシ・公式情報を調べ、必要なら家族に聞く。AIの検索補助を使う場合も出所・日付・店舗・量を確かめる。店名や「近所の最安」を家庭設定から捏造しない。

以下は同じ購入量・条件で比較する合成のチラシ価格：

| 買い足す物 | 近いA店 | 少し遠いB店 |
|---|---:|---:|
| 肉400g | 520円 | 480円 |
| じゃがいも1袋 | 260円 | 240円 |
| トマト2個 | 200円 | 200円 |
| 合計 | 980円 | 920円 |

> 子「B店なら60円安い。B店に行きたい」

この段階は候補の選択。買った記録にはしない。

### 05-D 移動・荷物・頼み方を考える

> 子「行きは歩けるけど、帰りの荷物を持てるか分からない。父に迎えを頼みたい。どう言えばいい？」

AIは荷物が危険と自動判定したり、車を手配したりしない。量や経路を家族と確かめる補助を出せる。今回は本人が助けを求めたいと判断する。

> AI「何をしたいか、手伝ってほしい理由、場所と時間を伝えると相談しやすいよ。相手が何時ならできるかも聞けるね」

言い方が浮かばない時は短い例を出せる。実際に本人が聞くところは代行しない。

### 05-E 現実に頼み、相手の都合を聞く

> 子（父へ）「B店で夕飯の材料を買いたい。帰りの荷物を手伝ってほしい。16時30分ごろ迎えに来られる？」  
> 父「A店なら帰り道で16時30分に寄れる。B店だと17時になる」

子がアプリへ戻って「聞いてきた」と報告する。父の発言を子が伝えた場合は、子から聞いた内容として残す。常時録音した父の原文にすり替えない。

### 05-F 条件を受けて選び直し、合意する

> AI「B店は60円安い。迎えは17時。A店は980円で、16時30分に迎えを頼める。帰宅は16時45分までの約束だったね」  
> 子「今日はA店にする。予算に入るし、父の帰り道で頼めるから」  
> 子（父へ）「A店に変える。16時30分に迎えを頼んでもいい？」  
> 父「それならできるよ」

AIがA店を確定するのではなく、本人が価格・時間・運び方・家族の都合を合わせて選ぶ。相談は本人の希望を押し通す練習ではない。相手の事情を聞き、実行できる案を作り、改めて合意する。

別の子なら献立・出発時刻・運び方を見直す案もあり得る。A店を唯一の正解としない。相手の予定や家庭ルールを本人が無断で変更しない。

### 05-G 実際に店へ行く

合成の時刻例：16時ごろ徒歩で出発、A店へ16時10分ごろ到着。道中はアプリ操作を要求しない。買い物中の相談・記録は安全に立ち止まれる時に任意で行う。

現実に確認するものは、売り場の値段・量・使う日に合うか・持ち帰れるか。チラシの予定価格と売り場の確認結果を分ける。

### 05-H 割安なパックを見つける

A店には肉400g・520円に加え、600g・600円のパックがある。

> 子「大きい方がお得と書いてある。そっちがいいの？」  
> AI「100gあたりは小さい方が130円、大きい方が100円。大きい方が割安。ただ、じゃがいもとトマトも買うと合計1,060円。今日使う量と、余った肉をどうするかも考えられるよ」  
> 子「今日は400gで足りる。トマトも買いたいから小さい方にする」

計算・単価の知識は直接補助してよい。必要量、支払総額、残りの使い道、食べたい物を本人が判断する。割安という一条件でAIが商品を指定しない。親に予算変更を相談する別案もあり、勝手な増額はしない。

### 05-I 支払い・帰宅・調理・食事

はるが実際に980円を支払い、父と16時30分に落ち合い、16時40分ごろ帰宅。お釣り20円は家庭へ返す。親と合意した工程を担当し、17時30分に4人で夕飯を食べる。

購入予定、購入結果、調理、食事は別の事実。レシートだけで調理や満足まで推定しない。親も実際に関わったことを確認する。写真を証拠として強制しない。

### 05-J 短く話して、記事を確かめる

> 子「B店の方が安かったけど、父の時間と合わなかった。肉は大きい方が割安だったけど、今日はトマトを買いたくて小さい方にした。次は2日分なら大きい肉も考えたい」

途中に記録した理由を全て再説明させない。本人が追加したいことだけ話せる。AIが記事を作り、本人が「ここは違う」と直せる。公開前の親確認は維持する。

記事の合成例：

> **おばあちゃんを迎える、980円の夕飯**  
> はるは家の材料を使い、4人分のカレーを計画しました。最初は920円のB店を考えましたが、父へ迎えを相談すると帰宅の約束に間に合わないと分かりました。そこで、父の帰り道のA店へ変更しました。  
> 売り場では割安な大きい肉も見つけましたが、必要な量と予算、祖母に出したいトマトを考えて400gを選びました。買い物は980円。親と調理し、4人で夕飯を食べました。  
> はるの言葉：「次は2日分なら、大きい肉も考えたい」

本人が話していない理由をこの例から埋めない。「全部一人でできた」「判断力が上がった」と断定しない。

## 6. 過程の記録から記事・新聞・アルバムへ

### 6.1 残すのは完成した答えだけではない

| 過程 | 記録の例 | 区別 |
|---|---|---|
| 最初の考え | B店が60円安いから行きたい | 本人の発言・候補 |
| 調査した情報 | チラシの値段、確認した在庫 | 情報源・確認時点・量 |
| AIの補助 | 単価の説明、依頼の要点 | AI／固定教材の支援。本人の発見ではない |
| 家族の返答 | A店16時30分、B店17時 | 発言者／報告者・出所 |
| 選び直し | 帰宅に間に合うA店にする | 本人の決定。理由は発言がある時だけ |
| 実行 | 980円で購入、帰宅、調理 | 実際の結果。予定から自動生成しない |
| 次に試したいこと | 2日分なら大きい肉も考えたい | 本人の希望。次クエストの強制開始なし |

音声認識、原文引用・数字の整理、記事の生成、保存・公開を別の処理として設計する。認識誤りを直せる。訂正時は関連する数字・記事にも反映し、承認済み公開内容の無断差し替えをしない。

未記録は未記録として残す。空欄は埋める宿題にしない。記事は本人の発言に根拠を持つ編集文と分かるようにし、AIが作った文を本人の引用にしない。

### 6.2 同じ記録を再利用する

同じ出来事 → 原文・確認情報 → 記事案 → 本人の修正／共有意思 → 親が内容版と相手を確認 → 新聞・アルバムで閲覧。

家族内の記録保存と祖母への共有は別。家庭の収入・支出・支援履歴を記事へ自動公開しない。本文に980円等があれば、その本文を共有すると金額も届くと分かるようにする。共有しない、返信しない、後で読む、祖母不参加でもクエストは成立する。

## 7. ポイント・ごほうび・次の行動

### 7.1 大きい報酬は、引き受ける範囲に対応

| 合意した範囲 | 仮の報酬 |
|---|---:|
| 指定食材の在庫を調べて伝える短い挑戦 | 10P |
| 家の仕組みを調べ、整理し、提案を一度試す | 20P |
| 一食の献立・買い物・相談・調理を引き受ける | 40P |

条件の数、質問回数、AIとの会話量、記事の長さ、安い商品、家族への従順さで増減しない。相手の都合や条件変化で修正する場合、合意した達成範囲を家族と確認する。AIが報酬・役割の有料／無料を決めない。

調査20Pと別日の夕飯40Pは別の合意した活動。前の在庫記録を再利用しても、同じ確認に別途10Pを重ねない。

### 7.2 状態を分ける

| 出来事 | 利用可能 | 確認待ち／取り置き |
|---|---:|---|
| 初回終了 | 0P | なし |
| 調査を親が確認し付与 | 20P | なし |
| 夕飯を終えて達成確認を依頼 | 20P | 40P確認待ち |
| 親が合意した実行を確認し、一度だけ付与 | 60P | なし |
| カフェ50Pを本人が申し込む | 10P | 50P取り置き |
| 親が承認し一度だけ消費、日程を相談 | 10P | カフェ未提供。50Pは消費済み |
| 実際にカフェへ行く | 10P | 提供済み。追加のポイント控除なし |

家庭のごほうび候補はカフェ50P、本80Pとする。本人が「今カフェに使う／本のために残す」を選ぶ。サービスの送金・購入代行ではない。却下は取り置きを解除。承認後に提供せず取り消す場合は戻す。再試行で二重付与・二重消費しない。

ポイントを得るための新聞公開や家族の返信を求めない。家庭へ返した食材費のお釣り20円と本人のポイント10Pを混同しない。

### 7.3 次の挑戦への入口

次に開くとき、本人の「2日分なら大きい肉も考えたい」を参照できる。別の献立で試す、違う題材にする、今はしないを本人が選ぶ。親子で人数・予算・期間を新しく確認する。

次の買い物で、本人が先に在庫を見たり迎えの都合を聞いたりするかを確認する。記事の完成、ポイントの増加、会話量で学び・判断力を認定しない。AIなし／少ない支援の別場面での行動は、今後の観察事項であり今回の実績ではない。
